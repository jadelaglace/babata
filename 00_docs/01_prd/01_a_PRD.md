# Babata 产品行为

## 1. 文档职责

本文把 `DOC-REQ` 变成用户可识别、可重复交付的产品行为。它不维护 P0-P9 历史、具体来源或课程
数量、运行批次、当前完成度和实现文件；这些分别属于归档、`DOC-USAGE`、receipt 和 Architecture。

## 2. 用户工作流

```text
给出资料或目标范围
  -> 预览范围、权限、动作、成本和风险
  -> 获取/登记原件或外部 snapshot
  -> 清洗与必要多模态理解
  -> 知识、案例、日志和感悟沉淀
  -> 检索、子库、年度册或其他可重建输出
  -> 验证、用户验收和可追溯关闭
```

用户可以只执行其中一个明确阶段；Babata 不因完成收集就自动启动清洗、知识登记或发布。

## 3. 通用运行模式

| 模式 | 可观察行为 | 不能声称 |
| --- | --- | --- |
| 试跑 / dry-run | 预览授权范围、动作、写入、限制、估计成本和失败条件，不写正式结果 | full run 成功 |
| 试点 / pilot | 对有界真实范围启用尚未普遍开放的能力，逐项报告结果和不可外推边界 | 全局可用 |
| 模板 / profile | 选择、版本化、验证并复用输出和清理合同，模板不拥有内容 | 某实例已接受 |
| 明确范围全量运行 | 处理声明分母中的每个对象，报告 success/failed/skipped/gap | 产品或全来源完成 |
| execution round | 冻结输入和终端，连续运行到终端后统一收敛缺陷 | 边跑边修后的可比结果 |

具体试跑、试点、模板接受和全量运行结果统一记录在 usage/evidence，不反向改写产品行为。

## 4. PRD-01：在来源上下文中选择性收集

1. 系统展示或生成带来源身份、时间、层级、类型、附件和限制的候选。
2. 用户或受控 Agent 明确选择范围后才进入 capture；未选择对象不写正式 C0。
3. 正常路线优先成熟官方能力、CLI/SDK、浏览器和现成工具；回退与限制对用户可见。
4. text、file、export、first-party 和已验证 prefetched handoff 最终进入同一个正式 writer。
5. 授权只覆盖声明范围；不因一次登录自动扩大到账号全量或其他来源。

## 5. PRD-02：逐项状态、重试和重收集

1. 每个对象独立返回成功、失败、跳过、不可访问、removed、changed 或 unchanged。
2. 局部失败不清除成功项；重试只执行失败或明确选定对象。
3. 重收集 unchanged 时只追加 observation，不制造 revision；changed 时追加可追溯新 revision。
4. 用户能够看到失败原因、是否可重试、下一动作和没有处理的范围。
5. 完整运行结束时给出冻结分母和终端矩阵，不用抽样或 checkpoint 冒充全量。

## 6. PRD-03：原件、第一方内容和派生保持可辨别

1. 原件/C0、第一方内容、C1 派生、知识记录、C2 输出和 C3 运行状态具有不同身份和 writer 边界。
2. 正式记录可以回到来源、revision、asset、hash、处理器和相关人工决定。
3. 第一方创作、批注、日志和感悟走同一正式链路，但不会因每次评论自动制造内容 revision。
4. 删除或重建 C1/C2/C3 不改变 C0、第一方记录、人工审阅或关系。
5. 失败、受限或 provenance 不完整的结果隔离，不静默提升为 ready/accepted。

## 7. PRD-04：忠实、可替换的多模态清洗

1. 用户可对正式输入选择处理器、profile 和范围，并在提交前看到预期成本与限制。
2. C1A 保存完整文字派生；C1B 增加理解本质所需的图片、音频、视频片段或附件判断。
3. 没有必要媒体时明确记录判断，不为数量凑模态；摘要不能替代完整文字。
4. 输出记录处理器/model/version/config、输入、状态、限制、usage 和完整性。
5. 多处理器结果可以并存、比较和重建；单项失败可重试且不覆盖原件或其他成功结果。

## 8. PRD-05：形成可持续的个人知识沉淀

1. 用户可以登记 Knowledge、Case、Log、Insight、Course 和它们的关系、来源和版本。
2. 机器建议类型、标签、关系、相关度或表达时保持 machine/unreviewed 身份；人工决定单独记录。
3. 内容可同时关联多个基石、Branch、Course 和非拥有型 lens，不被强制压入单一目录树。
4. 日志和感悟可以引用当时资料、知识和案例，形成可回看的认知轨迹。
5. 新 evidence 或大范围重构可以产生真实修订；简单再分析不伪造原内容版本。

## 9. PRD-06：第一方创作使用同一条资料链

1. 用户可创建、修订、批注和关联第一方内容，并保留作者、时间、来源和 revision relation。
2. 第一方输入可以接受忠实清洗、知识登记和输出，但原文始终可回读。
3. Agent 辅助写作或结构化必须标明机器参与，不能把建议冒充用户原话或已接受判断。
4. 取消、失败或并发冲突不得留下半成品正式版本。

## 10. PRD-07：检索、回看、关系和子库

1. 用户可按正文、来源、时间、类型、状态、标签和关系检索。
2. 搜索结果说明命中来源和限制；embedding 是增强召回，不替代稳定身份和显式关系。
3. 用户可从知识进入案例、日志、课程和原始证据，也可反向回看。
4. Sublibrary/lens 是版本化定义，同一内容可以出现在多个视图而不复制第二份权威。
5. 外部主权库可以先提供原结构/时间线/主题导航，只有选中对象才进入正式 promotion。

## 11. PRD-08：输出服务于真实使用

1. 用户从明确 input scope 和版本化 profile 生成 package；package 包含 manifest、hash 和 rebuild recipe。
2. 输出可以是 Markdown、JSON、Obsidian、年度册或后续真实需要的格式；未启用格式保持诚实状态。
3. publisher 只发布通过完整性和链接验证的 package 到唯一 live，不从 live 反写知识权威。
4. 用户可删除、重建或升级视图；旧 package、acceptance 和来源关系仍可追溯。
5. 课程输出提供可读标题、内部导航、必要媒体和复习图；控制面文字不进入知识正文。
6. Backs 年度归档按年份生成时间线、日志、主题、截图信息、感悟和证据索引，并回链 snapshot。

## 12. PRD-09：Skill、脚本和 Agent 是受控入口

1. 一个总收集 Skill 按来源 route/capability 分发；一个清洗入口按模态和 provider 选择 recipe。
2. Skill 解释范围、权限、风险和下一动作，调用正式能力，不自行创建第二持久化系统。
3. Agent 在一次授权范围内连续执行、轮询和可控重试；不会自动扩张来源、启动下一数据阶段或接受建议。
4. 脚本适合确定性编排和检查；复杂来源导航与语义工作由 Agent 使用真实工具完成。
5. CLI、本地 API 和未来 UI 组合同一 application service；入口不同不改变 writer 和安全边界。

## 13. PRD-10：本地权威、记忆档案和可恢复

1. 正式数据使用外部数据根，配置和凭据与仓库分离；敏感信息不进入普通日志、输出或 Git。
2. snapshot/backup 记录范围和完整性；恢复先进入隔离根并完成数据库、资产和 hash read-back。
3. Backs profile 在任何去重或垃圾清理前生成目录/hash/结构截屏；精确重复保留最旧实体及多位置关系。
4. 清理候选先可恢复隔离并留清单；近似内容不能作为精确重复自动删除。
5. 清理前后结构和有价值内容共同支撑“记忆宫殿”；截图等主动留存信号进入 OCR/视觉理解而非默认删除。
6. 外部同步只证明选定目标和范围；不会把 Git、Obsidian 或备份仓库变成运行 writer。

## 14. 产品范围

当前产品范围是本地 raw-to-view 链路及其受控来源、清洗、知识沉淀、检索、子库、输出和恢复行为。
当前版本、真实完成范围、暂缓对象、未实现 capability 和下一步只由 `DOC-USAGE` 维护。
