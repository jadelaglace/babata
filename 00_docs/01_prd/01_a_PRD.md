# Babata 产品需求文档

本文只定义可重复交付、对用户可观察的产品能力和行为。它不维护 P0–P9 进度、具体来源或课程
处理数量、批次名称、日期、某次试跑结果或当前 live 状态；这些事实统一进入

## 1. 产品定义

Babata 是一个本地优先的个人真实资料系统。它面对的不是单一收藏场景，
而是散落在平台、设备和个人创作中的真实资料从进入、保留、清洗、理解、
沉淀到再次使用的完整过程。

Babata 的价值不在于建立很多协议、接口或宏观架构，而在于让下面这条链路
长期可用，并且尽量低成本、低摩擦：

```text
外部来源 / 自己创作
  -> 收集
  -> 清洗和标准化接入
  -> 消化、吸收、沉淀、建模和管理
  -> 检索、子库、输出、传播和调用
```

产品成功不只意味着“资料已经入库”。资料还必须保留原貌和上下文，能够追溯、
理解、关联和长期管理，并最终能在需要时被找到、组织和使用。

## 2. 用户与使用起点

当前主要用户是 Babata 的拥有者本人。用户通常从以下情境开始：

- 正在飞书、浏览器、内容平台或聊天工具中阅读、收藏或整理资料；
- 已有一批平台导出件、本地文件、书签、媒体或历史记录需要收进来；
- 想写一篇新笔记、修改旧稿、记录反思，或对已有资料作批注和判断；
- 想回看、检索、比较、分析或重新组织已经积累的资料；
- 想把沉淀结果变成子库、报告、卡片、文章、网页或其他应用可用的输出。

日常使用不应要求用户理解内部数据结构，也不应要求手填导出路径、来源元数据或
候选协议。命令行可以服务自动化、恢复和运维，但不是正常收集体验的前提。

用户给出需求和优先级、选择授权范围并完成产品验收。Agent 维护由需求到实现、测试和证据
的闭环，承担范围内的普通技术判断；只有会改变产品意图、不可逆边界、数据权威、安全或
验收结果的选择才交回用户。

## 3. 四段产品边界

| 阶段 | 用户得到什么 | 这一阶段不做什么 |
| --- | --- | --- |
| 收集 | 在来源上下文中发现和选择资料，看到逐条进度，并把原件连同来源上下文可靠拿到 | 不深入理解、不做知识判断、不改写内容 |
| 清洗 | 得到可继续使用的文本、结构、字幕、关键帧和媒体信息，同时保留原件与处理记录 | 不覆盖原件，不把模型解释当成事实 |
| 核心 | 审阅、理解、记录、关联、分类、建模、评分、分析、沉淀并长期管理资料 | 不把自动生成结果静默升级为知识真相 |
| 输出 | 检索、阅读、筛选、回看、组织子库并生成各种可消费结果 | 默认不反向修改权威资料，不成为第二套存储 |

四段必须边界清楚，但对用户仍是一条连续链路。一个入口、适配器或视图不能绕过
这条链路成为隐藏的数据权威。

这条连续链路不是来源专属的紧耦合流水线。收集者把某一明确范围的真实原件、上下文和
限制正式交给统一 C0 后，该次收集已经完成，即使以后从不运行 C1 也成立。C1 是独立的
通用清洗结果：它引用并知道自己的 C0 输入，但 C0 不等待 C1，也不按 OneNote、豆包等
来源各建一套专属 C0/C1。

在收集内部，产品分别报告“主权拿回到多深”和“资料管理到什么状态”，二者不是一条强制
流水线：

| 维度 | 状态 | 用户实际得到什么 |
| --- | --- | --- |
| 主权深度 | C0-A1 | 当前直接可得的原始字节、响应或导出件已抢先保全，带来源、哈希和限制；不等待后续处理 |
| 主权深度 | C0-A2 | 让 C0-A1 内容本地完整所必需的正文、内嵌媒体和附件也已取得，未得部分明确列为缺口 |
| 主权深度 | C0-A3+ | 经单独判断继续取得有价值的语义引用；每个结果是独立 node/reference，默认低优先级并及时停止 |
| 管理就绪 | captured | 已在本地保全且可校验 |
| 管理就绪 | prepared / C0-B | C0-A2 已成立后，完成解压、稳定命名、格式识别、manifest 和字段保留等非语义准备，原件未被覆盖 |
| 管理就绪 | registered / C0-C | C0-A2 与 prepared 已成立，再由唯一 Rust application/core 正式登记，可通过 item/revision/asset/provenance/relation/status 回读 |

只有 `registered / C0-C` 对外称为“正式进入 C0”或“正式 C0”。C0-A1/C0-A2 的 captured/prepared
同样可以是已经成功完成的主权回收，不因尚未 SQL 登记而被说成“什么都没拿到”。
但 C0-A1 只能停在 captured：至少完成 C0-A2，才允许进入 prepared/C0-B 和 registered/C0-C。
C0-A3+ 是可选语义引用，不阻塞 B/C。

取得深度按明确授权范围逐项判定，不要求一个来源的全部历史同步推进。代表样本、试点范围和
全量范围必须分别显示；任一小范围通过都不能升级范围外对象或整个来源的状态。

## 4. 产品行为

产品支持四种容易混淆但必须分开的成熟度/使用方式：

| 方式 | PRD 定义的产品行为 | 不属于 PRD 的事实 |
| --- | --- | --- |
| 试跑 / dry-run | 在不正式写入或发布前预览授权范围、预计动作、限制、成本和失败条件 | 某次试跑用了什么输入、是否成功、花了多少 |
| 试点 / pilot | 对有界真实范围启用尚未普遍开放的能力，逐项报告结果和不能外推的边界 | 某个课程或来源试点的日期、数量和完成状态 |
| 模板 / profile | 选择、版本化、验证并复用输出结构与展示合同；模板不拥有知识内容 | 某个模板实例在哪个批次被接受 |
| 明确范围全量运行 | 处理授权范围内每个对象，保留逐项成功、失败、跳过和缺口，不用抽样冒充全量 | 某次 `N/N` 或某门课程是否已经跑完 |

具体试跑、试点、模板接受和全量运行结果统一记录在 usage/evidence，不反向改写产品行为。

明确范围的批处理以“执行轮次”为收敛单位。每轮在开始前冻结输入指纹、目标终端、阶段验收矩阵
和 fail-fast 风险类别；运行中持续记录阶段结果和缺陷，但不因普通缺陷修改正在运行的脚本、配置、
输入或验收口径。只有继续执行会破坏数据/权威/安全或使后续证据无效时才提前终止。其余缺陷在
分母内独立对象全部形成明确终态、到达目标终端后，统一按根因和影响范围归并成修复集；修复完成后从全新 staging 开启新轮，不把旧轮
局部续跑包装成完整复验。一次局部命令或目标测试不能代替整轮终端验收。

### PRD-01：在来源上下文中选择性收集

关联需求：00 §1、§3、§8。

用户连接来源并给出来源、收藏夹、会话、时间段或其他明确范围后，Agent/Babata 应
自己发现候选并继续完成该范围的收集，而不是把逐条确认、翻页和下载交给用户，也不
因为“连接成功”就静默扩大到未授权账号级全量。候选概览应随时可查看，并尽可能显示
标题、来源位置和层级、类型、更新时间、附件可得性及已知限制；只有范围有实质歧义
或会越界时才再次确认。

正常收集应能够从用户已经登录、阅读、收藏或整理资料的真实上下文开始。产品优先复用已
证明的官方导出、API/CLI、现有登录态或成熟工具；只有真实缺口反复出现时才增加窄适配能力。
每个来源当前采用的具体工具、证据等级、正常路线和回退由 source research/architecture 维护，
不写死在 PRD。
导出件、PDF、复制、截图和录屏可以作为恢复、离线传递或来源受限时的路径，
但不应被包装成所有来源的日常体验。

对聊天和封闭平台，产品只处理用户明确授权的导出、恢复材料或真实登录范围。上游归档、可得
原件、缺失清单和完整性证据始终保留；Recovery 不冒充正式 C0，筛选结果不覆盖原始导出。

浏览器路线必须落到具体平台，而不是把“浏览器”本身当作这些平台的共同来源。知乎、
Bilibili、小红书和抖音要展示真实收藏范围并取得所选正文/媒体；豆包、Kimi 和 ChatGPT
要展示真实会话范围并取得消息顺序、角色和附件；语雀要展示真实知识库/文档层级。
普通当前页、选区、书签和网页收藏仍作为独立浏览器来源，但不能替代点名平台的候选、内容、
附件和重收集证据。对浏览器书签，用户给出一次明确文件夹或集合范围后，Agent 应遍历其中的
网址并取得实际正文和可得附件；只保存标题与 URL 不算完整收集。

来源路线必须基于真实工具证据，并优先采用合法、稳定、完整且用户操作最少的成熟能力。
当正常路线不可用或需要付费、重开发或持续人工配合时，用户应能看到原因、代价和信息损失；
具体调查顺序、候选工具和采用结论由 source research 维护。

Agent 已经把明确范围的真实正文、附件和上下文拿回并校验后，当前收集结果可以成立，
不要求先开发平台专用适配器。需要重复执行时优先整理为 Skill；只有实际重复使用证明
现有工具或 Skill 仍缺稳定批量、重试或恢复能力时，才进入少量开发或更重开发。

路线优化固定按稳定、准确、真实、速度排序。前三项由真实范围和真实 C0 证明后，产品应
记录耗时与故障点，把重复导航、反复确认、整批中断和无结论工具分叉收敛掉。正常路线只
保留一个已证明方案及必要回退；速度优化可以复用浏览器或捕获生命周期，但不能合并候选
的 C0 事务、跳过完整性检查、隐瞒局部失败或放宽授权范围。

正常运行应是用户给出一次收集目标或范围，Agent 发起安装、登录或 OAuth 流程；用户
只在来源官方页面完成无法替代的登录、扫码或授权确认。之后的浏览器导航、命令、分页、
下载、重试、临时文件、格式接入和状态由 Agent/Babata 持续完成，直到该范围结束或出现
真正阻塞，不能把中间过程不断交还给用户。产品不得把手抄密码、Cookie、token、导出
路径或来源元数据设计成日常收集步骤。确实只能接收会话秘密的现有工具，必须先证明
没有更安全路线，并把秘密限制在本机受控存储中。

一个来源只有在能合法、可靠地取得真实内容、上下文、附件和限制，并通过重收集验证后才能
显示为已支持；预留名称、空接口、其他平台样本或通用浏览器 fixture 都不能替代该来源证据。

### PRD-02：收集过程可见、可重试、可重收集

关联需求：00 §3、§7。

一次收集中的每条资料都有明确的 `queued`、`running`、`saved`、`skipped` 或
`failed` 状态。失败信息应能让用户理解问题并重试；局部失败不影响已经成功保存
的资料。浏览器或外部 CLI 支撑的批量重采按单 item 隔离；一次瞬时失败不能中断其余
已保存 item 的验证，也不能让整批成功项重新运行。

对同一来源再次收集是正常操作。系统应区分 `changed`、`unchanged`、
`inaccessible` 和 `removed`，保留每次收集的时间、结果和来源变化，不用新结果
覆盖旧原件，也不把“暂时访问不到”误判为“资料已删除”。

成功收集的资料应尽可能带有来源链接或导出路径、平台、作者或账号、来源原生
标识、采集时间、来源时间、原始哈希或明确的完整性方法、附件、所在收藏夹/对话/知识库层级、
访问条件和收集工具版本。对明确选择的本地目录，默认逐文件直接复制并独立登记，不在热路径中
按大小、抽样或完整哈希做去重；完整 SHA-256 可以在以后显式验证。权限不足、内容不完整或附件
缺失必须保持为明确可见的限制。

### PRD-03：原件、第一方资料与派生物分开保留

关联需求：00 §4、§5、§7。

原视频、原图、原音频、原文件、原文和原导出件属于需要长期保护的资料。系统
不得因为已经提取文字、生成摘要或创建视图而丢弃原件。视觉、动态、语气、排版
和上下文本身都可能是内容的一部分。

来源平台生成的预览 PDF、转码媒体、截图或其他转换件不是上传源文件。源文件可取得时，
产品优先保存源文件，并把预览/转换件标成派生物或回退证据；不能用预览下载成功冒充原件
已经拿回。

OCR、转写、字幕、关键帧、视觉描述、摘要、标签、结构化结果和模型理解都是
与输入相连的派生物。它们可以重做、比较或删除后重建，但不能覆盖原件，也不能
伪装成人工确认过的事实。

用户应能从派生结果回到对应原件、输入版本和来源上下文，也能看出一项内容是
外部原件、第一方资料、机器派生结果还是可重建视图。

一批资料可以只完成原件收集并长期停留在 C0；产品不得因为尚未清洗而把这次收集显示为
未完成。后续何时、用什么处理器生成 C1，由资料模态和使用需要决定，不由来源收集器绑定。

### PRD-04：清洗独立、忠实且可检查

关联需求：00 §4。

清洗能够处理网页和文本提取、文档解析、PDF/图片 OCR、音视频转写、字幕、
关键帧、视觉描述、媒体元数据、格式统一和基础去重。多模态处理优先支持用户
选择的百炼 CLI，并为后续通义/百炼 API 或批处理保留可替换的处理方式。

每次处理都应记录输入、工具或模型、版本、状态、输出和哈希；失败可理解、可重试，
重跑不会改变原件。用户可以检查原件与派生结果的对应关系，并在资料积累后手动
触发明确范围的批处理。

清洗的目标是让资料可继续使用，而不是把所有内容压成一份“标准文本”。当转换
会损失视觉、时序、语气、版式或上下文时，C1B 应保留必要的本质模态和损失说明；完整原件
及其回看能力由外部主权库负责。

C1B 是清洗后的本质，不是原件保管层：外部主权库已经负责完整原件和原始结构。产品
可以只从长 PDF、PPT 或视频中裁出需要的图片、音频或视频片段，也可以只抽取附件中必要的
部分，形成 C1B 供 C2B 使用；没有必要的新增媒体时也可以只确认已有文字本质，不要求复制整个
载体或建立独立原文件回链。来源定位作为可选
溯源元数据保留，不能反过来成为片段可用性的门槛。

对课程和其他高信息密度资料，产品默认尽可能形成 C1B/C2B；C1B 先完成内容本质判断，再按
表达不可替代性选择是否保留多模态：
公式、图表、PPT 图示、乐谱、实物、人物、建筑和 UI 等视觉证据优先保留图片片段，片段可以
直接从视频帧、PPT 页面或长 PDF 页面裁出；有独立听觉价值时从视频抽取或裁剪音乐、音色、
环境声、SFX 或演奏音频；只有动作、手势、触键、操作过程、复杂镜头、动画、3D 材质变化或
真正高光依赖时间连续性时才保留视频片段；其他模态仍无法表达必要属性时增加模型、工程、原型、
数据集、字体、材质包和源代码等附件，附件也可以只抽取必要部分并与其他模态并存。可渲染文本是辅助表达，
不得替代无法可靠重绘的图片片段。证据尽可能记录来源载体和页码/时间段/裁剪框，但不要求
每个片段都能回链到独立原文件。C1A/C2A 仍可按用户明确要求使用，但不是新任务的默认目标。

### PRD-05：核心区支持理解、沉淀和长期管理

关联需求：00 §1、§2、§5。

核心区是 Babata 的主要价值所在。用户可以审阅收进来的资料，并对其进行理解、
记录、关联、分类、建模、评分、分析、沉淀和长期管理，而不只是浏览一份原始库
或全文搜索结果。产品核心是一个以用户为中心、高度结构化且动态演进的“个人知识宇宙”。

用户在工作时应能同时看到相关原件、派生内容、来源、必要历史和已有关系；可以形成
自己的判断、主题、结构和关联，并在确实改写同一作品时保留前后变化。具体交互形态暂不锁定，
但必须支持从“看过一条资料”走到“形成可回顾、可关联、可继续使用的个人沉淀”。

个人知识宇宙至少提供以下产品语义：

- 第一大界是“时间/空间/物质/意识基石 -> 学科 -> 分支”的地图；四基石是稳定、定义明确、
  可重叠的世界观观察维度，不是要求对象单选或强行穷尽的文件夹；第二大界是互为理论和实践
  证据的知识与案例；第三大界是长期、中期、短期、实时日志和第一方感悟；
- 学科与分支通过有类型、有依据的多父 DAG 演进；`subfield_of`、`intersects_with`、`draws_from`、
  `applies_to`、`prerequisite_of` 等语义不能压成同一种父边。内容可跨根、跨学科、跨层级归属；
  世界观模型或归属实际改变时保留必要历史，不把三大界扁平化为同一种记录；
- 课程拥有独立于专业分支的身份和版本，通过 `covers` 多对多覆盖稳定 Branch；一课可以覆盖多分支，
  一个分支可以被多课覆盖。课程内脑图可选择一个 MECE 主轴服务学习，但不能反向把宇宙地图
  压成单路径；
- MBA 作为版本化 Sublibrary/lens 聚合跨学科课程和内容，不作为单一 discipline 或唯一父节点；
  只有出现学分、必修/选修、培养方案、院校/年度版本等真实需求时才启用正式 Program 语义；
- 基石交叉先记录带依据、版本和作者/模型的等级或独立相关强度，置信度单独表达，默认不要求
  总和为 `100%`。百分比只能是声明分母与方法后的可重建归一化视图，不能冒充本体归属事实，
  也不能复用兴趣/战略/共识评分字段；
- 每项内容可记录兴趣（现在）、战略（未来）、共识（过去）三个相关度分量和综合分；
  默认权重为 `40/35/25`，权重配置、分值、依据和历史均可回看，且可用真实使用数据
  建议调整；
- 高密度表达可以使用文本脑图、Mermaid、模型、公式、清单、流程或提纲；图片渲染
  是可选的可重建视图，不强迫用户先画图才能沉淀知识。

模型可以提出摘要、标签、关系、分类、评分或分析建议，但这些结果必须标明是
模型输出。未经用户确认，它们不能自动成为事实、人工判断或唯一分类，也不能
覆盖与其冲突的原始证据；但“未审阅”不是阻塞状态，建议仍可进入检索、内容浮现、
关系导航、子库候选和输出候选。用户的接受、修改或拒绝保存为审阅标记；只有用户
实际改写或形成新内容时，才产生新的 first-party C0，而不是把机器记录改名为人工记录。

资料完成收集和清洗后，Agent 应继续提出来源齐全、结构可校验的类型、地图归属、标签、
关系、评分和高密度表达候选，并以机器生成、未审阅的身份进入核心。这个自动消化过程
不要求用户逐条写评论或制造修订；用户没有回应时系统仍继续工作。

### PRD-06：第一方创作走同一条资料链路

关联需求：00 §5。

用户可以新写笔记、草稿和反思，也可以修订已有作品或对其他资料写批注。第一方
创作不是绕过系统的特殊旁路：

- 新写内容形成一条新增资料；
- 只有真正改写同一作品时才形成可追溯的新版本，旧版本仍可回看；
- 批注是独立资料，并与被批注目标建立关系；
- 感悟是第三大界的独立第一方内容，日志是新的时间切片，附件和证据通过资产或关系补充；
- Agent 基于更多资料重新分析时形成新的 C1 处理结果，不冒充第一方作品修订；
- 人工判断与模型生成内容保持可辨别。

用户应能保留真正写作和改写时的原味，同时沿关系看到评论、感悟、日志、证据和后续分析。
版本不是每次普通交互的强制动作；删除任何生成视图都不能造成第一方内容或必要历史丢失。

### PRD-07：资料可检索、回看、关联和组织成子库

关联需求：00 §2、§6。

用户可以按正文、来源、时间、类型、状态、人物、人工分类、关系及处理情况查找
资料，并从结果继续回到原件、来源、版本、派生物和相关资料。

除主动搜索外，系统应根据三维相关度、关系强度、时间、当前方向和用户明确规则，
提供可解释的内容浮现或回顾入口。浮现结果说明“为什么出现”，允许区分人工确认、
模型建议和未审阅候选；它不以黑箱排序替代用户自己的地图和判断。

用户可以为了一个主题、项目、阶段或传播目标，把权威资料组织为分类子库。子库
应保存选择和组织逻辑，必要时可重建；它不是复制出一套需要手工同步的新权威库。
MBA 这类跨学科课程集合优先使用该版本化子库/lens 能力；子库只引用课程、分支和内容，
不取得它们的身份或写入权。

检索和回看不仅覆盖清洗后的文本，也应允许用户发现只有原始媒体、附件、来源
上下文或受限状态的资料，避免“没有可搜索文本”等同于“资料不存在”。

核心沉淀、评分/浮现、检索、关系导航、子库和输出共享同一权威资料与关系；在出现真实、
独立的部署或所有权边界前，不拆成需要同步的独立应用。Agent 和 Babata 的界面通过同一核心
工作，Obsidian 只是可删除重建的输出。

### PRD-08：输出服务于真实使用，不预设唯一形态

关联需求：00 §6。

用户可以把选定资料和沉淀结果输出为报告、卡片、文章、网页、阅读视图、可分享
内容或供其他应用调用的结果。输出既支持单项使用，也支持明确范围的大规模生成，
并保留必要的来源和版本信息。

输出形态由真实用途逐步确定，不在当前预设为某一个最终应用。Obsidian 可以是
可重建的阅读和展示形式之一，但不是唯一存储，也不要求用户手工维护生成内容。

输出和视图默认只读消费权威资料。删除、重建或更换一个子库、网页、Obsidian 库
或导出物，不应删除原件、第一方内容、派生结果、人工关系或历史版本。

课程输出在 C2B 阶段完成正式知识宇宙归属，并由 C2B package 同时生成可编辑 Mermaid 课程
脑图和 PNG 位图；Obsidian 只发布 hash 一致的 package 副本。课程 index 是课程内导航，不能
冒充或改写宇宙级大 Index。该能力遵守 `C2B-DOCS-FIRST-GATE` 和 `DOC-INDEX` 的唯一权威顺序；
只同步语义实际受影响的下游角色，所有必要合同与验收先于实现和正式登记/发布；`C2B-KNOWLEDGE-UNIVERSE-GATE`
与 `C2B-PACKAGE-OWNED-COURSE-MAP` 均通过后才显示可用。

`C1B-FORMAL-HANDOFF-GATE` 要求课程 C2B 只消费 Rust 核心回读通过的 C1B 账本：完整 C1 引用、
本质判断和必要媒体均保留 C0/C1 身份与 hash，staging sidecar 不能代替正式登记。正式发布还要
同时标记 C2B、Obsidian 导出和 `semantic-obsidian/v1` 模板状态；模板是可复用合同，Vault 仍是
只读兼容导出。

课程脑图还必须通过 `C2B-MECE-COURSE-MAP-GATE`：使用一个明确的分类轴，把知识章节分入互斥
且完整覆盖的一级分支；学习支持单独成层，不把内容分类、流程顺序、跨章依赖混成一张交叉图。
Obsidian 中的节点使用原生内部链接并能打开当前 live 课程笔记；PNG 在正文中使用显式、适中的
显示宽度，用户不需要先缩小页面才能看清全图。

课程图还须通过 `C2B-CRASH-COURSE-MAP-GATE`、`C2B-MODERN-VISUAL-MAP-GATE` 和
`C2B-RIGHT-GROWING-MINDMAP-GATE`。它不是章节目录的图形化复刻，而是从正式 C2B 正文提取的
课程压缩层：在每个互斥决策域呈现目标、关键判断、核心公式/关系和风险边界，达到“不点开正文
也能紧急补习”的信息密度；章节文件名节点继续承担原生内链。

视觉类型固定为传统右向思维导图：课程根位于左侧，profile/manifest 声明的知识域和学习支持
全部向右生长；一级知识域稳定分色，同域曲线继承该色。根、域、章节、知识细节逐层展开，文字和小圆点直接
附着在线路末端，不使用矩形/圆角知识卡、大片底色或左右双侧布局。知识细节保持短句且不可点击，
章节与学习支持保留精确文件名的原生链接；不保留只重复“课程知识”或域名称的空中间层。
具体嵌入宽度、最小等效字号、高宽比和 selector 由 accepted profile/TC 声明并在渲染结果上验证，
使整张图能在普通阅读视图中一次扫清，而不是把现代视觉理解为增加卡片、层级或装饰。

`C2B-RESPONSIVE-MAP-GATE` 要求课程 Index 默认只展开原生 Mermaid 主图，并让它随 Obsidian
笔记窗格自适应：Mermaid 开启 `useMaxWidth`，实际 SVG 具有百分比宽度、`viewBox` 和受控
`max-width`。同源 PNG 仍随 package 发布，但默认收进折叠 callout，仅作为打印、离线和渲染
回退，不再与主图重复撑高首页。该能力不宣称 Mermaid 自带图内滚轮缩放或平移，原生课程内链
仍保持可点击。

用户查看入口遵守 `OBSIDIAN-HUMAN-VIEW-BOUNDARY`：Agent 只启动注册 Vault 的正确 URI 并交还用户，
不使用 Computer Use 代替用户阅读或验收。具体课程当前入口只由 usage status/manifest 登记，
不写入可复用产品行为。

### PRD-09：Skill、脚本和 Agent 是受控入口

关联需求：00 §8、§9。

Skill 可以接收链接、文件和指令，提交给已经存在的收集或处理能力；脚本、浏览器
插件和模型服务也可以生产候选或读取结果。所有入口都应返回真实状态和失败原因，
不能在底层能力尚未实现或验证时声称支持。

用户和 Agent 只面对一个收集 Skill：`babata-collect`。它根据来源、范围和当前真实能力状态
选择内部 route/recipe；OneNote、印象笔记、豆包以及同一来源下的不同导出或附件形态不
形成多个用户级 Skill。平台新增内容形态时扩展原 route/recipe 和验收覆盖，用户不需要学习
新的收集入口。浏览器、飞书、桌面控制等成熟 Skill 或 CLI 是执行依赖，不是并列的数据入口。

`BATCH-ROUND-TERMINAL-GATE` 适用于 Agent 驱动的重复或多阶段批处理。Agent 在一轮内负责把
已冻结范围推进到声明终端，并保留完整的阶段结果、缺陷账、实际终端和验收矩阵；它不能把每个
局部 checker 变成人工或代码修复 gate。普通缺陷留到轮后统一修复，失效性风险则终止整轮并明确
说明未到终端。fail-closed 默认先隔离受影响的 item、课程或 package；只有共享风险让其余结果不再
可信时才终止整轮。任何修复都会产生新的执行轮次和 staging 身份，旧轮只作证据或比较输入。

这些入口不拥有最终资料，也不能绕过核心直接形成另一条持久化路径。用户触发一次并
给出明确范围后，Agent 应在该范围内连续自主完成收集或批处理，不把逐条确认、翻页、
下载和重试交还给用户。Agent 不因已经连接或技术上可以自动运行，就越过该范围擅自
扩大到账号级全量、自动改写资料或自动作出知识判断。

`babata-collect` 只把明确范围送到统一 Collector/Capture 并验证 C0；它不启动 Process、
不等待 C1，也不把“已拿回临时文件”“已正式登记 C0”“可长期稳定重跑”混成一个完成状态。
取得路线先抢救 C0-A1，再在直接依赖边界完成 C0-A2；C0-A3+ 只能作为显式、有限、低优先级的引用
取得任务。外围工具可以形成 captured；只有 C0-A2 完整性依赖闭合后才能形成 prepared 材料，
再经 Rust application/core 回读成功才形成 registered C0。C1/C2 发现缺口时只能提出新的
授权取得任务，不能反写已有 C0。

### PRD-10：本地优先、唯一权威和可恢复

关联需求：00 §7、§9。

Babata 在当前阶段作为一个本地系统工作。真实资料只有一条最终持久化路径；无论
资料来自浏览器、Skill、脚本、模型工具还是第一方创作，都经过同一套版本、溯源
和权威规则。

用户的真实原件、第一方资料、派生结果、视图和运行状态应具有清楚的数据级别：

| 级别 | 内容 | 产品行为 |
| --- | --- | --- |
| C0 | 原始资料、原始媒体、第一方资料及其版本 | 最高优先保护，追加新版本而不原地覆盖 |
| C1 | OCR、转写、摘要、标签、结构化结果和模型输出 | 与输入可追溯，可比较、重做和重建 |
| C2 | Obsidian、网页、子库物化结果和其他生成视图 | 可删除重建，不拥有 C0/C1 |
| C3 | 队列、缓存、日志和其他运行状态 | 可清理，不伪装成业务资料 |

代码、文档、测试和配置模板可以进入 Git；真实资料、数据库、模型输出、日志、凭据
和运行状态必须留在 Git 外。活动数据根只展示 C0–C3 的编号分区，不兼任开发工作目录。
开发验收证据与尚未正式收集的恢复材料使用各自独立的本地根，不能因移出活动数据根就
被误报为已进入 Babata，也不能提交 Git。备份与恢复应保护一致的资料状态，并能验证
原件、版本、关系和索引在恢复后仍然可用。

本表中的 C0 指 `registered / C0-C`。主权取得的 C0-A1/C0-A2/C0-A3+ 是取得深度，captured/prepared/
registered 是管理就绪状态；它们用于说明资料从平台风险中拿回了多少、离正式 C0 还差什么，
不增加新的 C0-C3 数据权威层级，也不在本次定义中要求新增数据库字段。

## 5. 人话词汇表与汇报规则

以下词可以用于内部实现和文档追溯，但用户不需要先学会这些词才能判断进度。产品界面、
进度地图和阶段汇报必须先说明“实际拿回了什么、现在放在哪里、还缺什么”，只有确实有助于
定位时，才在后面用括号补充工程词。不能只说“进入 C0”“有 7 个 asset”或“结果为
unchanged”，却不解释用户实际得到的结果。

| 工程词 | 汇报时先说的人话 | 准确含义 |
| --- | --- | --- |
| C0（正式 C0 / C0-C） | 已正式登记的原件和用户自己写的内容 | 从来源拿回并经唯一 Rust 路径登记、可回读的原文、原图、原音视频、原文件、原导出件，以及用户的第一方创作和历史版本 |
| C0-A1 / C0-A2 / C0-A3+ | 主权拿回深度 | C0-A1 抢先保存直接可得内容；C0-A2 补齐正文、内嵌媒体和必要附件；C0-A3+ 只在值得时有限追取语义引用 |
| captured / prepared / registered | 管理就绪状态 | captured 已本地保全；C0-A2 成立后才可 prepared；prepared 只做不覆盖原件的解压、命名、格式和 manifest；registered 才是正式 C0 |
| C1 | 从 C0 加工出来的内容 | OCR、转写、字幕、摘要、标签、结构化结果和模型输出；必须绑定可得的输入 identity 并可重做，不要求每个片段回链到独立原文件 |
| C2 | 随时可以重新生成的阅读或输出页面 | Obsidian、网页、报告、子库物化结果和其他视图；删除视图不等于删除资料 |
| C3 | 任务运行留下的临时状态 | 队列、缓存、日志和运行状态；可以清理，不冒充用户资料 |
| recovery staging | 临时回收区 | 可保存 captured/prepared 的主权材料；资料已经拿回本机并可供核验，但还可能没有经过 Babata 正式登记，不能冒充 registered C0 |
| Capture | 正式归档 | 把拿回的正文和附件交给 Babata 的唯一保存路径，记录来源、版本、文件指纹和关系，并能从 Babata 回读 |
| Asset | 附件或原文件 | Word、PDF、图片、音频、视频等二进制文件；汇报时应直接说文件类型、数量和是否为原件 |
| Item | 一份资料 | 一段对话、一篇文章、一个视频、一份文档或一条用户创作，是用户可理解的资料单位 |
| Revision | 这份资料的某次保存版本 | 来源内容或用户创作发生变化时追加的新版本；旧版本仍保留 |
| Hash | 文件指纹 | 用文件内容算出的稳定校验值，用于发现损坏、变化和重复；它不是资料标题或用户要填写的编号 |
| Recollect | 再收一次并检查变化 | 对同一明确范围重新读取，判断来源是否变化、暂时不可访问或已删除，不覆盖旧资料 |
| Adapter | 平台专用的长期收集代码 | 当现有 Agent、官方工具、CLI 或 Skill 不能稳定重复完成任务时，才开发的窄连接能力 |
| Skill | Agent 可重复执行的操作流程 | 告诉 Agent 如何使用已验证的浏览器、官方工具或命令完成一类任务；Skill 不是新的资料仓库 |

任务状态也必须翻译成用户能直接采取行动的结果：

| 状态词 | 人话 |
| --- | --- |
| queued | 已列入本次范围，正在等待处理 |
| running | 正在读取、下载或校验 |
| saved | 本次资料已经正式归档并可回读 |
| skipped | 按明确规则没有收，必须说明原因 |
| failed | 没有收好，必须说明失败位置、已保留的成功结果和能否重试 |
| changed | 来源和上次不同，已经或需要保存新版本 |
| unchanged | 来源和上次相同，没有重复保存新版本 |
| inaccessible | 这次暂时无法访问，不能据此判断来源已删除 |
| removed | 有足够证据表明来源已删除；Babata 中的历史原件仍保留 |

“闭环”必须明确说是哪一层，不能用一个词混过三种结果：

1. **Agent 收集闭环**：用户点名范围内的实际正文、附件和上下文已经拿回并校验，缺失和
   限制已经说明，并报告主权深度 C0-A1/C0-A2/C0-A3+ 与管理状态 captured/prepared/registered。
   它不要求先开发平台专用适配器或先完成正式登记。
2. **Babata 正式归档闭环**：拿回的资料已经经过唯一保存路径正式登记，来源、版本、附件
   和文件指纹可回读。资料只在临时回收区时，不能宣称这一层完成。
3. **长期自动化闭环**：同一类任务以后可以由 Agent、Skill、官方工具或必要的窄适配器
   稳定重跑，并正确报告变化、失败和重试。一次 Agent 成功不自动等于这一层完成。

阶段汇报应分别给出这三层的真实状态。某一层未完成时，应直接说明缺的动作及其对用户的
影响；不能用数据库行数、代码文件、测试通过或技术证据等级代替用户可见结果。

正文、内嵌媒体和使当前内容可用的必要附件属于完整性依赖，通常在 C0-A2 收口；文章、论文、
网页等被引用内容属于语义 reference，默认只记引用，只有明确价值与授权时进入 C0-A3+。后续
C1/C2 若暴露缺口，只生成新的取得任务；新结果作为独立记录或关系进入正常链路，不直接
修改旧 C0。

## 6. 来源范围

以下是产品期望逐步覆盖的来源范围，不代表已经启用，也不代表必须自建采集器：

| 来源组 | 代表来源 | 期望收集结果 |
| --- | --- | --- |
| 文档与知识库 | 飞书文档/Wiki/知识库、语雀、OneNote、印象笔记 | 正文、层级、附件、作者/时间和来源位置 |
| 聊天与模型对话 | 微信聊天、豆包、Kimi、GPT | 对话顺序、角色、时间、附件和上下文 |
| 内容与收藏平台 | 微信收藏/公众号/视频号、知乎、Bilibili、小红书、抖音 | 原始媒体或可得原件、标题、作者、链接、收藏上下文和限制 |
| 浏览器 | 当前页面、选区、书签和网页收藏 | 页面或选区内容、URL、标题、时间和书签层级 |
| 本地资料 | 文档、PDF、图片、音频、视频和平台导出件 | 原文件、路径/导出上下文、哈希和媒体信息 |
| 第一方创作 | 笔记、草稿、反思、批注和人工判断 | 原始措辞、版本、关系和创作上下文 |

同一次 OneNote 整本导出的 PDF 与 MHT 是同一来源的互补表示，只形成一个正式归档对象。
PDF 用于保留更接近 OneNote 的渲染和划分证据，MHT 用于保留图片、文字和格式；两份原件
都应可回看，不能把 PDF 页码当成 OneNote 原生 page/section ID。需要逐页或逐段使用时，
由后续可追溯的 C1 处理完成。

当用户明确给出多个 OneNote MHT 导出时，每个实际导出先形成独立、完整、可回看的 C0
归档对象，即使其中一个可能是另一个的子本或重叠范围。产品可以在候选和 manifest 中显示
确定性的文本重叠提示，帮助后续判断，但不能在 C0 自动合并、拆段或建立原生父子关系。
语义段落、重复内容和真实层级由后续 C1 产物提出，并保留机器未审阅与人工确认状态。

一个来源只有在真实授权路径、内容覆盖、附件、元数据、失败状态和重收集行为经过
验证后，才能显示为“已支持”。无法访问、只能部分收集或依赖手工恢复路径时，产品
必须如实显示能力和限制。

只有网页搜索到工具名或仓库、预留了 provider 文件、写出了导入格式，都不算完成
来源规划。必须同时说明最小授权、Agent 如何调用、实际验证证据和最后回退。

## 7. 产品范围与开放问题

Babata 当前产品范围是完整的本地 raw-to-view 链路及其受控来源、清洗、核心沉淀、检索、子库、
输出和恢复能力。具体 phase、已处理来源/课程数量、暂缓范围和当前下一步只由 usage status
维护，不在 PRD 中复制。

当前明确不做：

- 不把产品收窄成收藏器、导入工具、原始资料库或 SQL 查询界面；
- 不为了来源数量静默全量复制，也不先造覆盖所有平台的重型爬虫；
- 不让模型输出覆盖原件、替代人工判断或自动成为知识真相；
- 不要求用户手工维护清洗产物、Obsidian 或其他生成视图；
- 不让命令行、手填路径和手填元数据成为日常收集的主要体验；
- 不先做通用仪表盘、营销式前端或尚无真实用途的外部接口；
- 不因为四段逻辑边界而提前把它们变成多套互相复杂依赖的独立系统。

以下问题保持开放，由真实使用继续决定：

- 核心区最适合的审阅、关联、建模和长期管理交互形态；
- 输出能力最终留在核心中，还是在出现独立使用需求后形成单独应用；
- 飞书和浏览器之后各来源的实际优先级；
- 哪些自动化在资料与规则积累后可以从人工触发升级为人工确认或受控定时运行。
