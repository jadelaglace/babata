## 1. 文档职责与状态

本文记录 2026-08-07 用户提出的架构方向：外部资料库继续拥有自己的原件、目录、版本和内部状态，Babata 通过兼容口读取它们，生成可重建的 C2 导航，并按需将少量资料提升为 Babata C0/C1。

本文仍是**候选架构方向**，当前不覆盖 `00_a_REQUIREMENTS.md`、PRD、AC 或既有四段架构；用户已
授权把 MBA/Backs 兼容层列入试点计划，但试点通过前不升级为正式需求和架构。直接原话保存在
`00_requirements/00_c_USER_WORDING_RECOVERY.md`。

## 2. 核心判断

Babata 不应把所有外部资料强制压成统一的 C0、C1、C2。C0/C1/C2 是 Babata 的权威、处理和视图边界，不是所有外部系统必须服从的内部状态机。

目标模型是：

```text
外部主权资料库 / 外部 AI 系统
  -> 版本化兼容口
  -> Babata 外部库定义与扫描快照
  -> Babata C2 导航、搜索、回忆和关系投影
  -> 用户选择的资料再提升为 Babata C0/C1
```

“不强制清洗”不是不记录。Babata 至少保留外部资料库的身份、快照、相对路径、原生层级、对象 ID、版本/时间、完整性证据、访问限制和变更关系；这些信息是回忆上下文，不得因规范化而丢失。

## 3. 权威与所有权

### 外部主权资料库

外部资料库拥有：

- 原始字节、原目录、原生命名和原生版本；
- 外部系统自己的状态、权限、写入者和生命周期；
- 其目录结构作为回忆和恢复上下文的事实来源。

### Babata

Babata 拥有：

- 外部库的注册定义、扫描快照和增量记录；
- 自己生成的 C1 派生物、关系建议、审阅记录和 C2 导航；
- 用户明确提升后形成的 Babata C0 原件副本或 first-party 内容。

外部系统仍是自己的 writer。Babata 不能因为生成导航就取得外部库的写权限，也不能把外部 C0/C1 状态静默改名成 Babata 状态。

## 4. MBA 与 Backs 的统一解释

MBA 网站下载目录和 `D:\Backs` 都属于同一类“外部主权资料库”候选：

```text
网站/硬盘原始目录
  = 外部原始案例，保留原有结构

Babata 外部库快照
  = 路径、层级、哈希、时间、来源和增量证据

Babata C2
  = 面向回忆、检索、课程/事件/主题的导航与关系视图

选中的高价值资料
  = 可按需提升为 Babata C0，再独立生成 C1
```

因此，MBA 不必把网站全量文件都清洗为 C0/C1；可以保留完整网站目录作为外部主权资料，同时让 Babata 维护课程导航，只有真正需要阅读、总结、转写或长期检索的对象进入正式 C0/C1。

## 5. “宇宙”模型

知识宇宙、生活宇宙和密钥宇宙适合作为**语义、权限和导航边界**，不应默认成为三个物理数据根。

### 知识宇宙

课程、文章、研究、笔记、案例、知识关系和学习产物。适合较多使用 C0/C1/C2，但仍允许外部资料只提供导航。

### 生活宇宙

照片、聊天、设备快照、文件、地点、人物和生活回忆。原目录、时间、设备和当时的路径本身就是价值，不应为统一清洗而牺牲上下文。

### 密钥宇宙

如果指 API key、密码、恢复码、授权文件等秘密，应作为独立安全域处理，不进入普通 C1/C2 或模型输入。Babata 只记录存在性、用途、来源、状态和引用，不保存或展示秘密值。

一个外部库可以同时参与多个宇宙；宇宙是可版本化的范围/规则/权限定义，不是强制目录搬迁。

## 6. 兼容口候选合同

未来外部 AI 或资料系统不需要先转换为 Babata 内部 C0/C1。兼容口至少应能表达：

- provider、系统身份和 native schema/version；
- 稳定对象 ID、原生 revision/version 和时间；
- 父子目录、集合、标签或其他原生上下文；
- 正文/资产引用、原始路径和 hash/完整性方法；
- snapshot ID、增量游标或变更日志；
- 读取/打开能力、权限和访问限制；
- 结果是否仍由外部系统拥有，是否允许 Babata 提升为 C0。

Rust 核心仍负责验证版本、身份、路径、hash 和状态；TypeScript、Python、CLI 或外部 AI 只能提供候选快照，不形成第二个 Babata writer。

### 6.1 `external-sovereign-navigator` 导出模板

兼容层导出物由一个机器可读 manifest 和一个可替换的导航视图组成，最小字段为：

- `library_id`、owner/authority、provider、native schema/version 和挂载位置；
- `snapshot_id`、扫描时间、扫描范围、父 snapshot、增量游标和工具版本；
- 每个对象的稳定 native ID、原生相对路径、父节点/集合、原始名称、类型、时间、大小、
  hash/完整性方法和访问限制；
- `diff_status`：`added`、`changed`、`moved`、`removed`、`unchanged` 或 `inaccessible`；
- 可选的 Babata `c0/c1/c2` 关联和提升状态，但不覆盖外部状态，也不把兼容层结果伪装为
  正式 C0/C1；
- 导航 builder/profile 版本、输出 hash 和 rebuild recipe。

导航视图可以是 Markdown/Obsidian、HTML 或 JSON，但默认按外部原生树和记忆上下文呈现；去重
结果只增加“同一内容的多个位置”关系，不删除位置实例。更新时生成新 snapshot 和新导出，旧
snapshot、原路径和失败/不可访问状态仍可回看。删除导出物只删除视图，不触碰外部原件。

## 7. 增量与 C2 分叉

每次外部库更新形成新的 snapshot，而不是覆盖旧导航。同步结果至少分为：

```text
added / changed / moved / removed / unchanged / inaccessible
```

Babata 可以只为新增或变化对象补充 C2 导航，也可以从完整快照重建导航；两种方式都必须保留旧快照和 manifest。

同一个外部库可以有多个 C2 分叉，例如：

- 原始目录回忆视图；
- 课程或主题导航；
- 时间线/设备视图；
- 精确重复和近似副本审阅视图。

这些都是可删除、可重建、可换版本的 C2，不应反向改变外部原件或 Babata C0。

## 8. 还需要补的产品能力

1. `ExternalLibraryDefinition`：外部库身份、挂载位置、所有权、策略和权限。
2. `ArchiveSnapshot`：目录清单、相对路径、完整性证据和扫描限制。
3. `ArchiveSync/Diff`：新增、修改、移动、删除和不可访问检测。
4. `ExternalLibraryNavigator`：保留原结构的静态/交互式 C2 导航。
5. `ExternalAssetResolver`：打开前健康检查、哈希复核和路径迁移。
6. `Promotion`：用户选择对象后再进入正式 C0/C1 的窄路径。
7. `UniverseDefinition`：知识、生活、安全等宇宙的范围、权限和导航规则。

## 9. 试点顺序

MBA 全量处理收尾后，建议同时用 MBA 和 Backs 做小范围试点：

1. 不搬动外部原始目录，导入外部库定义和初始快照。
2. 用已有 manifest/去重证据验证增量 diff 和原路径保留。
3. 生成一个原始结构 C2 导航，再生成一个语义/课程 C2 分叉。
4. 只选少量对象提升为正式 C0/C1，验证外部库和 Babata 的双向溯源关系。
5. 用一次外部目录更新证明只补增量导航，旧快照和旧路径仍可回看。

## 10. 验收原则

- 外部原件和原目录结构不被 Babata 修改。
- 每个导航节点都能回到外部库、snapshot、原相对路径和完整性证据。
- 外部更新能区分新增、修改、移动、删除、未变化和不可访问。
- C2 删除/重建不影响外部库、快照记录或已提升的 C0/C1。
- 只有用户选定的资料才进入正式 C0/C1；不因“未清洗”而丢失或降级。
- 任何原生目录、对象 ID、时间和限制都不会因标准化而消失。
- 兼容层导出至少能证明一次完整快照与一次增量更新：精确重复只建立多位置关系，新增、修改、
  移动、删除和不可访问对象状态可读，且外部库仍是唯一 writer。

**原则总结：内容可以单实例化，历史位置必须多实例保留；规范化可以增加导航，不能替代原始结构。**

## 11. 信息价值、语义压缩和物理去重三轴

这条候选方向不只按 C0/C1/C2 选择处理深度，还需要把三个互相独立的策略轴分开：

### 11.1 记忆保真度

记录原始细节、目录、设备、时间、命名和上下文要保留多少。

- 生活资料：高保真，原路径和当时的目录关系本身就是价值。
- 课程资料：原始档案仍保留，但日常使用可以依赖更高密度的总结。
- 密钥资料：优先安全隔离，不进入普通内容处理链。

### 11.2 语义压缩比

记录允许被浓缩到什么程度。

- 生活资料通常低语义压缩，主要生成粗粒度导航。
- MBA 课程可以高语义压缩，把课件、转写和讲义浓缩成书、图、表、章节和要点。
- 缓存、临时文件和低价值残留可以只保留来源描述、清理证据或隔离状态。

语义压缩可以是有损的，但溯源必须是可回看的：任何书、图、表或摘要都要能回到原课程、原文件、原路径和具体输入范围。压缩内容不能替代原始证据。

### 11.3 物理去重作用域

物理去重回答的是“相同字节在什么范围内只存一份”，与资料的记忆价值不是同一件事。

推荐的基础模式是：

```text
content-addressed asset(hash)
  <- 多个 device/snapshot/path occurrence
  <- 原始目录树和历史快照引用
```

同一 Babata 管理库内可以强哈希后复用不可变内容；多个个人设备只有在都接入并完成扫描后才能确认跨设备重复。设备未连接或文件不可读时应保留 `unknown`，不能推断为不存在。外部库默认只记录重复关系，不未经授权修改外部文件。

服务器常见的 CAS、snapshot/manifest、namespace/tree、Git pack 或 restic/Borg pack 都属于可参考的成熟模式。小文件 pack、块级去重和透明压缩可以作为以后按实测收益增加的存储优化，不是 MBA/Backs 第一批必须建设的能力。

### 11.4 策略矩阵

后续可以为每个宇宙、外部库或资料类型声明一个 retention/compression profile：

| 类型 | 记忆保真度 | 语义压缩 | 物理去重 | 默认结果 |
|---|---:|---:|---:|---|
| 生活资料 | 高 | 低 | 接入范围内允许 | 原结构 + 粗导航 |
| MBA 课程 | 中/高（原档案保留） | 高 | 接入范围内允许 | 原档案 + 课程导航 + 高密度 C1/C2 |
| 缓存/临时残留 | 低 | 高 | 允许 | 描述/证据/隔离或清理候选 |
| 密钥/凭据 | 高完整性 | 禁止普通语义处理 | 受专用安全库控制 | 仅安全引用和状态 |

这个矩阵是候选策略，不改变外部资料的所有权，也不把所有对象强制提升到正式 C0/C1。
