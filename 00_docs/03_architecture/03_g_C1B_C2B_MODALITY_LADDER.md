本文只记录已确认的 C1A/C1B、C2A/C2B 模态差异、派生和删除边界；它不替代
`00_a_REQUIREMENTS.md`、`03_a_ARCHITECTURE.md` 的通用分级与 writer 约束。外部主权库保留原始
结构和完整原件的前提已由上游采用，不依赖任何 navigator candidate。

## 1. 核心判断

把 A/B 设计成同一信息的两个处理变体，比把它们当成互相覆盖的等级更清晰：

```text
外部主权库 / 原始原件
        |
        +--> C1A：确定性文字证据（抽取、OCR、ASR、结构化文本）
        |          |
        |          +--> C2A：只依赖文字证据的语义导航
        |
        +--> C1B：完成内容判断后的清晰本质（可读内容按需带多模态片段）
                   |
                   +--> C2B：消费清洗本质的语义导航
```

- C1A/C1B 是处理衍生物；C2A/C2B 是可删除、可重建的语义输出，不是新的来源层。
- C1B 不是 C1A 的媒体附加层，也不是原件保管层；它是对内容本质完成判断后的清洗结果。
  C1A 的文字可以复用；必要时才增加图片、音频、视频片段或附件，新增媒体可以为零。
- C2B 不能自行从原件补出媒体。缺少必要非文字证据时，必须先创建 C1B 增量，再重建 C2B。
- C2A 可以升级为 C2B，但路径是 `C1A -> C1B 判断/增量（可为零增量） -> C2B 重建`；保留旧 C2A 版本以便比较和回退。
- 新的 C2 工作默认以 C2B 为目标；只有用户明确要求只做文字导航时，才生成 C2A。
- C1A 只表示文字证据已抽取；C1B 表示本质判断已完成。C1B 即使没有新增媒体，也生成 C2B，
  不因为“没有片段”退回 C2A。

模板树、课程叶文档、正文质量、profile hash 和发布步骤属于 output spec/profile、`DOC-PROCESS` 与
MBA rollout，不在本架构补充维护。这里唯一约束是：模板不能绕过 C1B 本质/模态判断，媒体数量由
内容不可替代性决定，C2B builder 不得回到外部原件自行补证据或成为第二 writer。

### C1B 的边界

C2B 的内部实现以可删除、可重建的知识数据库/语义载荷为准；不在 C2B 用户层保存完整 C0
或 C1。外部主权库继续保存原件、原始目录和完整 C0/C1 证据，Obsidian 只是从 C2B package
物化出的兼容导出层，不能反向成为第二个权威 writer。

C1B 是“清洗后的清晰本质”，不是原件保管层，也不是原始证据镜像层：

- 外部主权库/C0 负责完整原件、原始目录、原始文件关系和记忆上下文；
- C1B 负责把内容清洗成可直接理解和继续组织的本质；视觉形式、听觉内容、连续时序或二进制
  属性本身有必要时，以相应片段或附件保留，不能用文字可靠替代；
- C1B 可以只保存从长 PDF、PPT 或视频中裁出的一个图片区域、一个音频片段、一个视频片段，
  或附件中真正需要的部分；不要求复制整个载体，也不要求维持载体目录结构；
- C1B 的片段、转码件和附件是派生结果。C2B 发布时必须物化所需内容或继续保留 C1B 资产；
  用户确认删除 C1B 物化文件后，必须保留 C2B 资产或可重建 C1B 的 manifest/recipe。

## 2. C1B 的范围

C1B 的多模态处理按“表达不可替代性”分四类。四类可以同时成立，不是互斥的降级链；同一
知识对象可以同时保留图片、音频、视频和附件。这个分类帮助控制视频和附件的过度保留，
不是 C1B 的固定配额，也不是把所有内容压成少量高光：

| 维度 | 类型 | 处理原则 |
| --- | --- | --- |
| 1 | 图片 | 公式、图表、PPT 图示、乐谱、实物、人物、建筑、UI 等，默认尽量保留可读的图片片段；可以直接从 PPT、视频帧或长 PDF 裁出，不要求存在独立图片原件。 |
| 2 | 音频 | 音乐、音色、环境声、SFX、演奏和其他听觉证据；可以从视频抽取或裁剪音频，不要求保留整段视频。 |
| 3 | 视频 | 只有动作、手势、触键、UI 操作、复杂镜头、动画、3D 材质变化或真正高光依赖时间连续性时才保留视频片段；2–3 小时通常只留约 3–5 分钟量级，按不可替代性调整。 |
| 4 | 附件 | 当文本、图片、音频和视频仍无法表达对象的必要属性时使用，如模型文件、工程文件、可交互原型、数据集、字体、材质包和源代码；可以与其他模态并存，也可以裁剪、抽取或转换，C1B 不要求再次保存完整原件。 |

Agent 可以使用 `ffmpeg`、OpenCV、Pillow 或其他受控工具完成筛选、裁剪、抽取、转码和质量检查；
片段本身就是 C1B 证据，不应被模型生成的文字替代。若能定位来源，记录来源载体 hash、页码、
时间段、裁剪框或附件内部路径；这些只是溯源元数据，不是 C1B 成立或长期保留的前置条件。
工具输出先进入 staging；候选必须绑定可得的 C0 revision/asset/hash，并记录处理器版本和限制才可登记为 C1B；
页码、时间段、裁剪框等更细来源定位是可选元数据。

`C1B-FORMAL-HANDOFF-GATE`：正式 C1B 不以 staging 目录为权威。完整 C1 可以复用已有 active
derivative，不重复登记；每项本质判断登记为 `structured_result`，每个必要视觉片段登记为
`key_frame`（其他模态使用对应 kind），全部由 Rust core 导入 managed C1。课程级注册账本必须
逐项携带 C0/C1 身份、run/derivative、logical path 和 output hash，并由 C2B builder 强制校验；
旧 C2B package、外部原件和 Obsidian Vault 均不能补写该账本。

## 3. 判定与升级规则

1. 处理对象时先判断内容本质及其表达方式；公式、图表和 PPT 类图示默认进入图片候选池，
   可从视频帧、PPT 页面或长 PDF 页面直接截取。
2. 独立听觉价值存在时，抽取或裁剪音频；如果同一对象还需要连续画面，音频与视频同时保留。
3. 动作、手势、触键、操作、复杂镜头或真正高光需要连续时间时，另保留视频片段，不能用音频或
   单帧图片替代。
4. 对其他模态仍无法表达的必要属性，增加附件；附件可以与图片、音频或视频并存，也可以只抽取
   必要部分。
5. 各层都只删无意义重复，不为“少量”而删除必要证据。证据尽可能带来源定位，但片段不因缺少
   独立原文件链接而失效；如果存在对应 C1A 或来源载体身份就记录，但 C1B 自己的片段 hash、
   格式、处理记录和内容才是该派生物的权威。
6. 只有用户明确要求或已采用的工作流触发后，才从未完成 C1B 判断的 C1A 生成 C2A；新工作流默认优先准备 C1B/C2B。
7. C2 的机器记录必须写 `variant: c2a|c2b`。界面可以把未加后缀的“C2”显示为最新可用版本，但不能改变历史记录的真实 variant。
8. 同理，机器记录必须写 `variant: c1a|c1b`；新界面中的“C1”默认指最新完整派生，历史 C1A 不被追溯改名。

## 4. 权威关系与删除

- 外部主权库：原始目录、原始文件名、完整原件、快照和增量 diff 的唯一权威。
- C1A：文字证据派生，可重建；在对应 C1B 判断或 C2B 验证完成前按需保留。
- C1B：完成内容判断后的清洗本质；可以复用 C1A 文字，也可以增加必要媒体，数量按表达需要决定，
  不以固定“高光”配额为门槛；
  但不继承外部原件的保管责任；只有通过核心登记并能由正式账本回读时才称为正式 C1B。
- C2A/C2B：语义导航和学习视图，可删除重建；删除 C2 不删除外部主权库或 C1。

当用户确认 C2B 已足够且希望节省空间，可以按 retention profile 删除 C1A/C1B 的物化文件；
外部原件不在此删除范围。删除前必须核对 C2B 物化资产或 C1B 的可重建 manifest/recipe，保存
输入/输出 hash、处理记录和可获得的来源定位。是否删除由用户逐库决定，不能由 C2 builder 自动执行。

## 5. 保持开放的实现选择

- UI shorthand 与机器 variant 的展示规则；
- 各来源的图片标准化参数、视频片段处理参数和附件保留策略；
- C1B 选择器、媒体质量检查和附件 resolver 的最小可运行接口。
