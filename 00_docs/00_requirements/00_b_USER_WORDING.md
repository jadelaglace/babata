## 1. 文档职责

本文是日常读取的**当前有效用户意图集**，位于恢复账本与 interpreted Requirements 之间。内容来自
用户原话，但允许不改变原意的标点/格式整理、明显错字修正、非文明表达纠偏和逻辑去冗余，因此
不是逐字引文，也不使用 Markdown 引号块。当前可执行需求仍由 `00_a_REQUIREMENTS.md` 拥有。

这里只保留仍有效的价值判断、约束和真正开放的张力。明显过时、反复纠结、被新决定完全覆盖的
方案，以及具体批次/分母/运行结果不进入本文；需要最后恢复时查
[`00_c_USER_WORDING_RECOVERY.md`](00_c_USER_WORDING_RECOVERY.md)。不得把 Requirements 的技术化解释
反向写回本文并声称是用户原话。

状态：`stable` 表示当前持续有效；`conditional` 表示条件出现才启用；`open` 表示用户尚未决定。
归因：默认为 `user-curated`；其他归因必须逐项声明。

## 2. 核心目的与责任

状态：`stable`。归因：`user-curated`。恢复词：`真实用途优先；低摩擦取回；用户验收`。

- Babata 要以用户为中心，把散落在平台、设备和外部资料库中的个人资料省心取回、忠实保存、
  清洗理解并沉淀为可长期使用的个人知识宇宙。
- 真实内容、真实路线和用户最终能使用的结果优先于宏观协议、漂亮接口和抽象完整。
- 用户负责需求、优先级、价值判断与最终验收；明确范围内的调研、实现、跑批、证据和收敛由
  Agent 承担，不把日常技术审批负担推回用户。

## 3. 四段链路

状态：`stable`。归因：`user-curated`。恢复词：`收集；清洗；知识宇宙；输出`。

- 链路是：收集和初步归档 → 独立的多模态清洗 → 消化/沉淀/建模/管理 → 子库、分类、传播与输出。
- 逻辑分层不等于提前拆仓、拆服务或设计跨模块接口；先用一个本地优先系统跑通真实闭环。
- 输出是否未来成长为独立应用仍是 `open`；当前决定只是不要为了概念完整提前拆分。

## 4. 收集

状态：`stable`。归因：`user-curated`。恢复词：`成熟路线；最窄开发；手工最后；C0`。

- 优先使用官方批量导出、成熟 CLI/插件/脚本和 Agent 可操作的真实路线；缺口再做最窄开发，
  人机配合或纯手工是最后手段。
- 用户明确来源和范围后，Agent 应尽量一次授权完成，不逐项打扰；未授权的新范围不得自动扩张。
- 收集以忠实 C0 为终点，保留正文、附件、上下文、来源身份和真实失败；不能因为收到了内容就
  自动触发 C1、接受知识建议或伪造完整性。
- 微信 UI 默认禁止 Agent 操作，除非用户另行明确授权；其余来源也遵守各自真实授权边界。

## 5. 清洗与多模态

状态：`stable`。归因：`user-curated`。恢复词：`保持原味；多模态本质；处理器可替换`。

- 清洗要忠实、可追溯、尽量保持原味；付费模型或工具可以用于提升质量，不以零成本为目标。
- C1B 保留完整文字与理解不可替代的图片、音频、视频片段或附件，不为凑模态设置固定配额。
- 原视频、原图、原音频、原文件和原目录由其主权边界保存；Babata 派生层可删除重建。
- 具体处理器可替换、互补；Babata 是长期集成者，不与某个 provider 或临时工具绑定。

## 6. 个人知识宇宙

状态：`stable`。归因：`user-curated`，其中交叉本体结论为
`agent-analysis-user-adopted`。恢复词：`三大界；四基石；Course/Branch；MBA lens`。

- 知识宇宙以“我”为中心，包含世界观/学科/分支地图，互相印证的知识与案例，以及长期、中期、
  短期、实时日志和第一方感悟；统一标签与显式关系贯穿各界。
- 动态相关度区分兴趣（现在）、战略（未来）和共识（过去），允许随真实使用调整并保留历史。
- 机器可以建议类型、标签、关系、评分和高密度表达；未审阅建议不冒充人工事实，也不因用户未
  逐项决定而阻塞检索、导航和后续候选。
- 用户整体采用的 Agent 分析是：四基石稳定、定义严谨但可重叠；学科/分支形成受约束多父 DAG，
  父边与交叉/应用/前置等关系分型；Course 与 Branch 身份分离并通过多对多 `covers` 关联；MBA 是
  非拥有型 lens 而不是单一 discipline；基石强度与 confidence、动态相关度分离且不强制合计
  100%；课程内单轴 MECE 不反向压扁宇宙本体。
- 改变四基石必须显式版本化；只有出现真实学分、培养方案和院校/年度需求时才启用 Program。

## 7. 输出、子库与阅读视图

状态：`stable`。归因：`user-curated`。恢复词：`可重建输出；Obsidian 只读视图；唯一 live`。

- 沉淀内容应能大规模检索、组织、形成子库、传播并按真实用途输出；输出形态随真实调用生长。
- Obsidian 是可删除、可重建的兼容阅读视图，不是权威存储或第二 writer。
- MBA 课程完整经过 C1 → C1B → C2B，每课独立登记、验证和验收，只发布一个用户可见 live；
  课程内部 Index 不冒充宇宙级大 Index。
- 知识正文只写知识；工作要求、存储解释、模型说明和控制面信息不得污染正文。

## 8. 数据、版本与外部主权

状态：`stable`。归因：`user-curated`。恢复词：`唯一 writer；外部主权；派生可重建；去重不丢位置`。

- 代码、文档权威与大体量运行数据分离；真实数据、媒体、数据库、日志、模型输出和秘密不进 Git。
- 原件和第一方内容具有最高权威；核心 writer 唯一，版本、来源、处理和人工决定可追溯；派生层、
  索引和导出可删除重建。
- 自带完整结构和记忆上下文的外部主权库继续拥有原件；Babata 可为其建立热插拔兼容导航，
  不强制洗成自己的 C0/C1/C2 目录。
- 同一库内物理相同文件可以去重，但必须保留它在多个语义位置和原始结构中的关系。
- 是否进一步形成知识、生活、密钥等多个“宇宙”保持 `open`，不提前制造新服务或分类体系。

## 9. 交互、自动化与技术边界

状态：`stable`。归因：`user-curated`。恢复词：`一次授权；窄 UI；Rust 核心；外围工具`。

- 明确范围内尽量自动完成；只有不可替代的登录/授权、范围歧义、不可逆风险或用户价值判断才暂停。
- Agent + 窄 UI 是当前方向，CLI 不应成为日常负担；移动端、桌面端和最终交互形态仍是 `open`。
- 稳定权威核心优先 Rust；易变外围按现成生态使用合适工具。语言和模块边界服从真实用途，
  不为架构美观提前建立服务、协议或跨模块 API。
- 最终外部同步/恢复目标仍是 `open`；稳定要求是可恢复、隔离恢复验证且不把 Git 当运行数据仓。

## 10. 工作方式与文档治理

状态：`stable`。归因：`user-curated`。恢复词：`docs-first；完整轮次；可恢复；用人话`。

- 新的治理输入必须先留下可恢复锚点，不能在长时间分析、挂机或上下文压缩后丢失最新目标。
- 新 session、交接、中断、暂停、上下文压缩或用户要求“继续/恢复”都不能改变当前目标和已完成
  状态；不确定内容应按未知处理，不能擅自重开已解决事项或用临时工作替换用户正在等待的结果。
- 重复工作应以完整轮次推进到声明终端，再统一记录缺陷、成组修复和完整复验；不要走一步卡一步，
  也不要用临时小测试冒充阶段验收。
- Agent 应承担明确范围内的连续执行和阶段恢复，汇报使用用户结果语言，必要术语同时给人话解释。
- 具体写入位置、队列、阶段结论、终端清理和 Git 流程由 `DOC-INTENT-PLAN-GOVERNANCE` 与
  `DOC-PROCESS` 统一定义，不在本文维护第二份操作合同。
