## 1. 文档职责

本文定义产品行为的可观察通过/失败条件，不保存当前结果、运行步骤、批次数字或用户验收历史。
每次真实执行的 terminal matrix 和 receipt 属于 Git 外 evidence；当前状态只查 `DOC-USAGE`。

## 2. 通用判定规则

1. 每项结论绑定明确授权范围、输入 identity、实现/config identity 和证据。
2. 工程 gate、产品 TC、真实路径结果和用户 acceptance 分开报告。
3. `success / failed / skipped / changed / unchanged / inaccessible / removed / deferred` 不压成一个状态。
4. fixture、文件存在、编译或单个样本不能单独证明真实工作流或更大范围完成。
5. 未实现、未授权、暂缓和开放项保持显式，不因 P0-P9 收官倒签。

## 3. AC-01：来源上下文中的选择性收集

追溯：`PRD-01`。

通过条件：

- 候选包含稳定来源身份、原始上下文、附件/资产和访问限制；
- 未明确选择的候选不进入正式 C0；
- 选定对象经同一正式 writer 写入并可回读；
- 路线、授权范围、回退和缺口可解释。

失败示例：把登录后可见内容全量自动导入、用 locator/fixture 冒充正文、外围脚本直接写正式库。

## 4. AC-02：逐项状态、失败与重收集

追溯：`PRD-02`。

通过条件：

- 每个对象有明确 terminal 状态和 reason；
- 局部失败不清除成功项，重试只执行目标对象；
- unchanged 不产生新 revision，changed 追加可追溯 revision；
- 完整轮次能核对冻结分母、成功、失败、跳过和缺口。

## 5. AC-03：原件、第一方内容、派生和视图可辨别

追溯：`PRD-03`、`PRD-06`。

通过条件：

- C0/first-party、C1、knowledge、C2 和 C3 具有可查询的数据类与 writer；
- 任意派生能回到稳定输入、revision、处理器和完整性证据；
- 删除/重建 C1/C2/C3 不改变原件、人工判断或其他成功结果；
- 事务失败不留下伪 ready 或孤立资产。

## 6. AC-04：清洗忠实、可检查、可重试

追溯：`PRD-04`。

通过条件：

- 完整文字、结构、来源语境和处理限制没有被摘要静默替代；
- C1B 对必要模态给出逐项有依据的保留/不保留判断；
- processor/model/config、输入、usage、价格依据、状态和输出 hash 可回读；
- 多结果可并存，失败项可重试，任何结果都不覆盖原件。

## 7. AC-05：核心区形成可持续个人沉淀

追溯：`PRD-05`。

通过条件：

- Knowledge、Case、Log、Insight、Course 和关系具有稳定身份、来源和版本；
- 基石、Branch、Course、lens、相关度和 confidence 不混用；
- 机器建议与人工接受可辨别；
- 日志/感悟能回链当时资料、知识或案例，并保留演化关系。

## 8. AC-06：第一方创作与版本关系完整

追溯：`PRD-06`。

通过条件：

- create/revise/annotate/cancel/concurrency 行为可验证；
- 普通评论、附件或再分析不被强制伪造为内容 revision；
- Agent 辅助内容标明机器参与，原文与用户决定可回读；
- 失败或冲突不产生半成品正式状态。

## 9. AC-07：检索、回看、关系与子库可用

追溯：`PRD-07`。

通过条件：

- 稳定字段检索与语义增强均返回可解释来源；
- 可以在知识、案例、日志、课程、外部对象和原始证据之间双向导航；
- 同一内容可进入多个 sublibrary/lens 而不复制权威；
- 删除并重建物化视图后，定义和上游身份保持一致。

## 10. AC-08：输出可追溯、可批量且不反写

追溯：`PRD-08`。

通过条件：

- package 声明输入 scope、profile/version、builder、限制、manifest、hash 和 rebuild recipe；
- 链接、媒体、标题、正文边界和完整性检查通过后才可发布；
- publisher 只复制已验证 package，唯一 live 不成为 writer；
- 删除/重建/升级输出不改变知识、C1B 或历史 acceptance；
- Backs 年度册每个重要结论能回到 snapshot、原文件/路径和证据范围。

## 11. AC-09：Skill、脚本、浏览器入口与 Agent 受控

追溯：`PRD-09`。

通过条件：

- 入口调用同一 application service 和 writer，不维护第二数据库或隐式状态机；
- Agent 不越过授权范围，不自动启动下一处理阶段或接受机器建议；
- 需要登录、不可逆、安全或价值判断时正确暂停；
- 失败、轮询、可控重试、取消和逐项状态可观察。

## 12. AC-10：本地权威、记忆档案和恢复成立

追溯：`PRD-10`。

通过条件：

- 正式数据和凭据不进入 Git；快照、备份和 restore 范围可验证；
- 隔离恢复能够打开数据库、验证资产/hash、识别可重建缺失且不切换活动根；
- Backs 清理前 snapshot 完整，精确重复判定可复核，保留最旧实体和全部 occurrence；
- 垃圾候选规则、清单和可恢复隔离成立，近似内容不会被当作精确重复自动删除；
- 清理前后结构截屏、年度分析和原始证据保持可追溯。

## 13. AC-11：完整本地 raw-to-view 闭环

追溯：`PRD-01..10`。

一个声明范围只有同时满足以下条件才通过：

1. 真实授权输入进入受控 C0 或外部 snapshot；
2. 适用对象完成忠实 C1/C1B 或给出明确不处理状态；
3. 适用知识/日志/感悟由正式 writer 登记并可回读；
4. 输出 package 可重建、可验证并发布到唯一 live；
5. 用户可从输出回到知识、派生和原始证据；
6. 隔离恢复或等价恢复验证不依赖活动副本；
7. 未完成、暂缓、失败和不适用范围完整列出。

TC-11 是这一标准的验证场景；它存在不等于当前已经有独立系统级执行回执。

## 14. 不属于产品验收的事项

- Issue、PR、代码行数、文件数和提交数量；
- 单独的编译、lint、fixture 或 targeted repair test；
- 未声明分母的“基本完成”；
- 用户未执行的设备实测；
- 由历史 phase 关闭推导出的新 capability 可用性。
