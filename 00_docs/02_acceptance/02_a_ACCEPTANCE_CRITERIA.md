## 1. 文档职责

本文把 PRD 转成可观察的产品通过/失败条件。它不维护当前 phase、批次、日期、Issue、课程数量、
文件计数或“已经通过”的执行结论；当前结果只在 `../04_process/04_b_USAGE_STATUS.md` 和 Git 外
receipt 中维护。测试如何执行见 TC，稳定技术边界见 architecture/spec。

AC 描述“什么结果足以证明能力成立”，不是项目日记。试跑、试点和模板可以为 AC 提供证据，
但某次试跑/试点的数字和完成状态不进入 AC。一个明确范围全量跑完，只证明那个使用范围完成，
除非它同时覆盖本 AC 声明的产品能力，否则不证明 PRD 或整个 phase 完成。

## 2. 通用判定规则

1. 通过必须同时有真实授权输入、用户可观察结果、权威 read-back 和适用的负向/重建证据。
2. 骨架、接口、fixture、候选文件、脚本存在、编译通过或单纯文件计数不能独立证明产品通过。
3. 样本、试点、单来源、单课程和全量范围必须明确标注分母，不允许彼此外推。
4. 工程 gate、产品 AC、TC 执行结果和用户验收是不同维度；任何一个不能静默替代另一个。
5. 未实现、未授权、受限、暂缓、跳过、失败和不可访问保持可辨别，不压成一个 `complete`。
6. 当前通过状态和证据位置只由 usage status 维护；本文只在产品完成口径改变时更新。
7. 局部 checker、修复测试和中间文件只证明对应观察点；批次/阶段通过必须由声明终端上的完整
   验收矩阵和轮次证据证明。

## 3. 产品验收标准

### AC-01：来源上下文中的选择性收集

关联产品行为：PRD-01。

通过条件：

1. 用户给出来源和明确授权范围后，可以看到真实候选、来源层级、类型、附件可得性和限制。
2. Agent 在范围内完成翻页、读取、下载和逐项处理；只有授权、登录或实质范围歧义才交回用户。
3. 所选正文、原件、必要附件和上下文按当前可得深度保存，缺失或受限项明确列出。
4. 一个来源只有在自己的真实内容、附件、失败和重收集路径经过验证后才显示为支持；其他平台、
   通用浏览器 fixture、locator-only 或空 adapter 不能代替。
5. 试点和全量范围分别显示；代表样本通过不升级来源外或范围外对象。

### AC-02：收集状态、失败与重收集

关联产品行为：PRD-02。

通过条件：

1. 每项结果具有 `queued/running/saved/skipped/failed` 或等价清楚状态和可理解原因。
2. 单项失败不丢失成功项；重试只影响目标项，取消后不继续扩张范围。
3. 再收集区分 `changed/unchanged/inaccessible/removed`；unchanged 不制造新 revision/asset。
4. changed 追加可追溯版本，inaccessible 不冒充 removed，非重试失败不无限循环。
5. 批量运行结束时能逐项核对输入分母、成功、失败、跳过、缺口和未处理范围。

### AC-03：原件、第一方资料、派生物和视图保持可辨别

关联产品行为：PRD-03。

通过条件：

1. C0、first-party C0、C1、C2 和 C3 在身份、存储、权限和用户呈现上可区分。
2. `registered/C0-C` 只能由唯一 application/core writer 写入并 read-back；captured/prepared
   如实显示尚未正式登记。
3. C1 绑定稳定 C0 identity/hash 和处理记录；失败或删除 C1 不改变 C0。
4. C2 可删除重建，不拥有 C0/C1、人工关系或 first-party 内容，也不成为第二 writer。
5. C0-A1/A2/A3+ 深度与 captured/prepared/registered 就绪状态分别报告；A1-only 不越级进入 B/C。

### AC-04：清洗忠实、可检查、可重试

关联产品行为：PRD-04。

通过条件：

1. 每个启用的清洗能力展示输入、processor/model、版本、状态、限制、输出和 output hash。
2. 文档/网页提取、OCR、转写、字幕、关键帧、视觉描述或媒体 metadata 只有在真实样本通过后
   才显示可用；未启用能力明确拒绝。
3. 失败可在不改变原件的前提下重试；多次结果可并存、比较和回溯。
4. C1B 先保留完整可读文字，再按“文字是否不可替代”选择图片、音频、视频和附件片段；
   不为凑模态保留，也不以摘要替代完整 C1 文字。
5. C2B 不直接读取外部原件补写媒体；删除/重建 C1/C2 不改变外部主权库或 C0。

### AC-05：核心区能够形成可持续的个人沉淀

关联产品行为：PRD-05。

通过条件：

1. 真实 C0/C1 可形成知识、案例、日志、感悟和关系，并归入三大界的可演进地图。
2. 四基石保持稳定定义并允许同一对象多维关联；系统不强迫四选一、不把“未知”伪装成已归类，
   改变四基石时创建可追溯 WorldviewMap 版本。
3. 学科/分支多父边只表达声明的 `subfield_of` 语义；交叉、应用、前置等使用可区分关系。内容可
   跨根/学科/层级多重归属，新增归属不被单路径 registrar 静默删除，变化保留必要历史。
4. 课程 identity/version 与 branch identity 可分别读回；一课可 `covers` 多分支、一个分支可由
   多课覆盖。MBA 可作为版本化 Sublibrary/lens 聚合课程但不成为单一 discipline 或内容 writer。
5. 基石等级/独立强度有依据、作者/模型和版本，置信度分开；默认不强制总和为 `100%`。任何归一化
   百分比标明分母/方法且可删除重建，不覆盖正式关系，也不混入兴趣/战略/共识评分。
6. 兴趣/战略/共识及综合分、依据和权重版本可读；默认 `40/35/25` 可调整且不改写历史。
7. 机器摘要、分类、关系、评分和分析始终标记 model/依据/未审阅；接受、修改、拒绝可追溯。
8. 未审阅建议可继续用于检索、浮现、导航、子库和输出候选，但不冒充人工事实。
9. 至少一种高密度表达可从文本重建；可选图片删除后正文与结构仍完整。

### AC-06：第一方创作与版本关系完整

关联产品行为：PRD-06。

通过条件：

1. 新笔记、草稿、反思等作为 first-party C0 进入同一权威链路。
2. 只有真正改写同一作品才追加版本；旧版本可读且不可原地覆盖。
3. 批注、感悟、日志、附件和 Agent 再分析分别形成独立资料/关系/C1，不伪造作品版本。
4. 人工判断、第一方正文、机器建议在创建、检索、输出中可辨别。
5. 删除编辑器缓存或 C2 视图后，first-party 内容、版本和关系可从权威层恢复。

### AC-07：检索、回看、关系与子库可用

关联产品行为：PRD-07。

通过条件：

1. 可按正文、来源、时间、类型、状态、人物、分类、关系和处理状态组合检索。
2. 可按三维相关度和综合分筛选/排序，并看到权重版本和依据。
3. 至少一种可解释浮现入口说明“为什么出现”，并区分人工、机器和未审阅。
4. 只有媒体/附件或无文本的资料仍能按 metadata/关系找到。
5. 子库定义保存用途、选择范围、人工 include/exclude、组织规则和未审阅策略。
6. 子库定义与人工判断属于权威资料；物化文件/索引可删除重建。
7. 沿地图、标签、证据、日志、版本和来源导航无静默断链；受限/缺失目标显示状态。
8. MBA lens 可按定义聚合多个 discipline/branch/course；删除或重建 lens 不改变课程、地图节点、
   semantic assignment 或课程的 accepted/closed 状态。

### AC-08：输出可追溯、可批量且不反写权威资料

关联产品行为：PRD-08。

通过条件：

1. 用户可对单项或明确范围生成至少一种人读输出和一种结构化输出；每次都有范围、版本和状态。
2. 输出保留用途所需的来源、版本、输入 identity/hash 和引用，能够回到权威资料。
3. 只有真实实现并验证的输出形态显示可用；试跑、试点和模板状态显式，不能由文件存在推导。
4. 输出默认只读；修改或删除输出不改变 C0/C1、first-party、关系和子库定义。
5. 同一范围和版本可重建；外部非确定性差异被记录，不静默声称逐字相同。
6. 模板/profile 是版本化的可复用输出合同，不拥有知识内容；模板实例的接受状态属于 usage。
7. 全量运行必须绑定明确分母并逐项报告，不用代表样本或成功项计数冒充全量。

C1B/C2B 与 Obsidian profile 还必须满足以下跨文档门禁：

- `C2B-DOCS-FIRST-GATE`：能力变更沿 `DOC-INDEX` 的唯一权威顺序 review；真实受影响的语义、合同和
  验收必须先同步，未受影响角色记录 reviewed-unchanged，再实现/发布。
- `C1B-FORMAL-HANDOFF-GATE`：正式 C2B 只消费可回读的正式 C1B 与知识宇宙登记。
- `C2B-KNOWLEDGE-UNIVERSE-GATE`：课程 C2B 发布前已进入正式知识宇宙；课程 index 不冒充宇宙级大 Index。
- `C2B-PACKAGE-OWNED-COURSE-MAP`：Mermaid/PNG 先在 package 生成，publisher 只复制并验 hash。
- `C2B-MECE-COURSE-MAP-GATE`、`C2B-CRASH-COURSE-MAP-GATE`：课程图分类清楚且包含可复习内容，
  不是目录膨胀。
- `C2B-MODERN-VISUAL-MAP-GATE`、`C2B-RIGHT-GROWING-MINDMAP-GATE`：视觉遵循 accepted profile，
  不因样式牺牲内容或链接。
- `C2B-RESPONSIVE-MAP-GATE`：只默认展开响应窗格的 Mermaid 主图；PNG 为折叠回退。
- `OBSIDIAN-HUMAN-VIEW-BOUNDARY`：用户要求打开时只启动课程 manifest/usage status 登记的唯一
  live URI，不代替用户查看；课程可仍处于 `pending_user_acceptance`。

profile-specific 节点数、尺寸、selector、文件名和媒体数量由 accepted profile/TC 验证，不作为
Babata 全局 AC。当前哪一门课程通过见 usage status。

### AC-09：Skill、脚本、浏览器入口与 Agent 受控

关联产品行为：PRD-09。

通过条件：

1. 外围入口返回与核心一致的真实状态、限制、失败和结果引用；能力不可用时拒绝而非模拟成功。
2. 入口只调用受控 application/core，不直接写 SQLite、最终资产、知识事实或第二套权威。
3. 用户触发一次并给出明确范围后，Agent 在范围内持续执行；取消和授权边界有效。
4. `babata-collect` 是唯一用户级收集入口，按 capability/recipe 路由；disabled/unavailable/unknown
   分别给出真实原因和下一动作。
5. C0 收集与 C1/C2 处理分开；收集成功不等待 C1，也不自动启动知识判断。
6. Skill 只有在被调用能力自己的真实 AC/TC 通过后才激活；Skill 测试不能替代产品能力证据。
7. 批量 Agent 对单项失败局部重试并继续其余项，不扩张范围、不自动接受模型建议。
8. `BATCH-ROUND-TERMINAL-GATE`：每轮开始前记录冻结范围、输入 identity/hash、目标终端、阶段
   验收矩阵和 fail-fast 类别；开轮后不得静默改变这些条件。
9. 非失效性缺陷被记录但不触发轮内修脚本/改配置/换输入，后续仍有意义的阶段继续执行到目标终端；
   数据破坏或不可恢复风险、权威/授权越界、安全问题、输入漂移或使下游证据失效的合同错误必须
   终止本轮，且不得发布本轮候选。普通 fail-closed 只隔离受影响对象；分母内其余独立对象仍须
   到明确终态，不能残留 `queued/running`。
10. 本轮只在目标终端形成一次阶段结论，列出每个验收项、全部观察缺陷、实际终端和未覆盖项；
    中间 checker 结果不能独立把轮次或阶段标为通过。
11. 终端后按根因和影响范围形成一个修复集；修复阶段可以运行针对性测试，但任何修复后都必须
    从新的 staging/round identity 完整重跑，旧轮不得通过局部续跑转成 accepted/closed。

### AC-10：本地权威、数据分级与恢复成立

关联产品行为：PRD-10。

通过条件：

1. Git 只含代码、文档、测试、迁移和模板；真实资料、SQLite、模型输出、日志、凭据和视图留在
   配置的数据根/受保护本地配置。
2. 活动数据、evidence、recovery、staging 和用户导出用途分开，不因路径相近互相冒充。
3. C0/first-party 追加保护，C1 可追溯重做，C2/C3 可删除重建；writer 和 read-back 路径明确。
4. 一致快照/备份覆盖必要数据；恢复只写全新隔离根，不自动覆盖或切换活动根。
5. 恢复验证检查 manifest/hash、SQLite quick check/foreign keys、C0 损坏 fail-closed 和凭据重授权。
6. 缓存、视图或日志缺失不冒充 C0 丢失；真正权威数据损坏阻止恢复通过。

### AC-11：完整的本地 raw-to-view 闭环

关联产品行为：PRD-01 至 PRD-10。

首个系统级闭环同时满足：

1. 从真实授权来源选择并收集资料，同时创建 first-party 内容。
2. 原件、上下文、版本和附件可回看；真实清洗可追溯且不改变原件。
3. 核心形成至少一项人工判断/关系，并保留机器建议身份。
4. 可检索、回看、组织子库并生成可追溯输出。
5. 删除重建输出后权威资料不变；隔离恢复后同一链路可读。
6. 注入局部失败后成功项保留、失败项可重试且无伪成功半成品。

某个来源全量、某批存量 registered、某门课程 C2B 或某个模板 accepted 都是使用证据，不能
单独替代以上系统级闭环，也不能由 AC-11 反向要求所有来源/课程全量完成。

## 5. 不属于产品验收的事项

以下内容可以是工程 gate 或证据组成部分，但不能单独证明 PRD/AC 完成：

- 目录、文件、trait、endpoint、命令或 adapter 已创建；
- fixture、mock、候选 JSON、locator 或单元测试通过；
- 一次 dry-run、pilot、模板渲染或代表样本成功；
- 某个明确使用范围 `N/N` 跑完；
- 编译、lint、数据库 migration、静态门禁或 hash 数量通过；
- 某个 C2 页面、Obsidian Vault 或报告文件存在。

它们只有在覆盖相应 AC 的真实输入、用户结果、权威 read-back、负向边界和重建要求时，才成为
该 AC 的一部分证据。执行结果记录在 usage status/receipt，而不是回写本文。
