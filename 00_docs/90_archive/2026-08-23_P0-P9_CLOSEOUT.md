## 4. 真正保留下来的经验

### 4.1 目的先于抽象

- 先让用户的资料拿得回、留得住、看得懂、找得到、用得起来，再决定模块、API 或独立应用。
- 优先成熟官方导出、CLI、浏览器和现成工具；只为真实缺口做最窄开发，手工是最后回退。
- 代表样本证明机制，不证明全量；一个范围 `N/N` 只对声明分母成立。

### 4.2 权威与派生必须分开

- 外部原件、Babata 正式记录、C1 派生、C2 输出、运行状态和凭据是不同数据类。
- 正式身份和状态只有 application/core writer 可写；Skill、脚本、Agent、模型和 Obsidian 都不是
  第二 writer。
- 派生和视图应可删除重建；任何摘要、课程书、年度册或导航都要能回到稳定输入和完整性证据。

### 4.3 自动化必须诚实

- 一次授权后 Agent 承担连续执行、重试、成本记录和证据收敛，不把日常技术审批推回用户。
- 未授权、失败、不可访问、跳过、暂缓、删除和未实现必须分开报告，不能压成 `complete`。
- capability 状态与来源证据、用户范围、逐项结果和 usage acceptance 是不同坐标。

### 4.4 跑批以完整轮次收敛

- 开轮冻结范围、输入、代码/config identity、目标终端和失效条件。
- 轮内继续所有不被共享失败污染的独立工作，记录缺陷但不边跑边改实现。
- 到终端一次性汇总矩阵和 defect ledger；成组修复后从全新 staging 开新轮完整复验。
- targeted check 只证明修复，不能冒充整轮、phase、release 或用户验收。

### 4.5 Docs 是控制面，不是历史仓库

- 新治理输入先落到正确角色；当前需求、产品合同、运行状态、原话证据和计划不能互相替代。
- Active Plan 只保留唯一当前项、受限队列和恢复结论；完成历史进入归档、Git 或 receipt。
- 恢复先核对 Goal/task-state，再读唯一 `CURRENT-ACTIVE`；缺失上下文是 unknown，不是重跑授权。
- 历史文档可以归档，但独有原话、已采用决定、失败恢复和未完成义务必须可检索、可回读。

### 4.6 多模态和输出服从内容本质

- C1B 是完整文字加不可替代模态判断，不是固定配额；没有必要媒体也可以得到完整判断。
- C2B 是可重建的高密度学习/使用视图，不得把控制要求、模型解释或存储说明污染到知识正文。
- publisher 只复制通过 hash 验证的 package；用户在真实工具中验收，Agent 不代替用户看。
