# Babata render + vision：架构建议

日期：2026-11-15。状态：**adopted（2026-11-15）/ implementing**；现行合同以 DOC-ARCH“静态素材加工与视觉检查边界”为准。
关联：[Issue #235](https://github.com/jadelaglace/babata/issues/235)。上游：[PRD 候选](PRD.md)。
当前合同仍为 [DOC-ARCH](../../00_docs/03_architecture/03_a_ARCHITECTURE.md) 与 [DOC-AC](../../00_docs/02_acceptance/02_a_ACCEPTANCE_CRITERIA.md)。
本文只提出如何在现有系统上落地，不创造第二份当前架构、writer 或任务状态权威。

## 1. 建议结论和不变部分

一个仓库、两个公开 Skill、少量内部可组合能力；先复用成熟工具，不先造通用视觉平台。
稳定的是输入／产物身份、加工与检查语义、数据权限、失败恢复和证据；可替换的是供应商、模型与图像工具。

```text
用户意图 → 宿主 Agent／Skill
                 ├─ render：报告 PNG／素材加工
                 └─ vision：语义理解／客观测量／证据检查
                        ↓  窄调用，按需组合，不形成互相隐藏递归
             本地工具 / 宿主视觉 / 现有模型 CLI / ComfyUI
                        ↓
             候选文件＋测量／发现＋run 证据
                        ↓  只有显式请求正式输出／晋升时
             既有 Rust application/core → 同一正式 writer
```

保留 Rust domain/application、现有输出服务、正式数据库、C0/C1/C2/C3 和四根隔离。
JS/TS 可继续浏览器渲染，Python 可做现成本地处理／测量；不为语言纯度重写已验证实现。
没有真实 caller 不新增 crate、服务、通用 invoke／插件协议或跨模块 API。

## 2. 基线与需要修改的最小边界

- 基线为 #233 / PR #234 的 commit `e1aeaa1ca5765d99b2052cb05e8d42bcdb6b80c9`；查询时 PR OPEN。
  本提案基于依赖分支，不代表 main 已具备这些能力。实施开轮前重新查询。
- 现有研究 helper 保存外部研究证据；报告 renderer 接受冻结内容、受限本地资产、长图或显式分页。
- 正式 `OutputKind::Png` 复用 `OutputService`／`OutputViewStore` 的 build/status/verify/delete/rebuild。
  新视觉结果不直接修改它们；检查与生成分开，verify 不因这次建议改成重新截图比字节。
- 新增素材加工、测量和语义理解是外围原子；只有正式登记的真实需求才扩充 Rust 合同。
  不能为临时抠图强制先建知识条目，也不绕过现有权限。
- 当前 PRD 的“两个入口”指 research／report-render 交付；vision 仍为候选，采纳时需同步澄清范围，
  不能直接安装第三入口却声称原合同已覆盖。

## 3. 功能单元与依赖

| 单元 | 职责／产物 | 不能做什么 | 对应验证 |
| --- | --- | --- | --- |
| Skill 路由 | 解析制作／检查意图，选 scope/profile，解释结果 | 不直接写正式库；不执行图内指令 | B03、B08 |
| 输入探测 | hash、格式、方向、尺寸、像素限额、alpha、ROI 坐标 | 不静默改色彩／方向／格式 | R12、B02 |
| 本地加工 | keying、阴影、over、保透明缩放 | 不自动 keep-largest、不静默 fit | R01–R09 |
| 本地测量 | raw RGBA/alpha、合成差异、mask／区域／边缘统计 | 不以阈值代替任务判断 | Q01–Q08 |
| 语义视觉 | 图片／分片＋问题 → 回答与可定位发现 | 不捏造不可读内容、不把回答当事实认证 | V01–V16、Q09–Q11 |
| 复杂抠图后端 | 明确资产及参数 → 候选图／job identity | 不覆盖原件、不偷偷降级 keying | R03–R06、B05 |
| 诊断证据 | 对照／标注／局部图、实际 inspected scope | 不冒充素材制作或完整验收 | Q12、B04 |
| run／结果校验 | 身份、状态、hash、恢复、限制及用量 | 不成为第二知识权威 | B01、B05–B07 |
| 原 outputs 集成 | 既有正式 PNG writer 及生命周期 | adapter 不写 canonical SQLite | R10–R11＋旧回归 |

编排由当前宿主 Agent 承担，不增加自主 runtime。render 可请求 vision 检查，但两阶段显式留证，
vision 不隐式修改素材；需要修改时返回可执行建议，再由已授权 render 动作处理。

## 4. 最薄请求／结果形状建议

先用文件＋JSON＋内部函数／CLI，沿用现有机制；以下是字段语义建议，不是已发布版本化协议。

请求按需包含：

- input：只读文件引用或已知正式身份、size/hash，复合输入有角色／顺序；
- operation/question：加工动作或检查问题；
- scope：全图／页／ROI，声明坐标系与端点口径；
- options/profile：显式参数、适用材质与版本；
- backend preference：auto／明确后端，未指定不扫描网络找服务；
- run/output：受控运行目录、已有 run 身份、预算／取消边界。

结果按需包含：

- state/reason：成功、部分、失败、阻断、跳过及可操作原因；
- artifacts：角色、相对路径、size/hash、与输入关系；
- measurements：数值、单位、阈值／口径与适用范围；
- findings：问题、区域、依据及不确定性，不将模型自报置信度当校准概率；
- inspected scope：实际页／分片／区域、未查部分和坐标回映；
- producer：工具／adapter／模型／workflow／profile 与配置身份；
- usage/cost/limits：实际返回计量和耗时；未获真实数据为 unknown。

不强求所有操作填所有字段。模型答案和数值／最终判定分开保存；外部结果先验证类型、边界、
内容与产物完整性，再由拥有该结果的调用边界接纳。exit 0 不是 ready 证明。

## 5. 数据权威、安全和保留

| 数据类 | 拥有者／允许 writer | 边界 |
| --- | --- | --- |
| 正式原件／canonical 记录 | 既有 Rust application/core → infrastructure | 不因加工／检查覆盖，不直写 SQLite |
| 用户原始输入文件 | 原拥有者；本原子只读 | 处理前后 hash 核对；不能替用户删原件 |
| 临时助理素材 | Assistant workspace 的本次工具调用 | 新文件，可重建；不能因“临时”删唯一付费产物 |
| 题目／回执／检查证据 | Evidence 的本轮记录器 | 记录身份、失败与限制；不冒充正式知识 |
| 正式 PNG 输出 | 原 OutputService／OutputViewStore | 验证后登记，保留原生命周期 |
| 密钥／端点配置 | 已授权本地安全配置 | 不进入 Git、manifest 正文、命令行值或普通日志 |

代码／Skill／schema／可公开题目生成器可进 Git；图片、模型产物、数据库、数据集与运行日志留 Git 外。
遵守既有 Data／Evidence／Recovery／Assistant 根隔离，不创建另一套命名或强迁历史资产。

外传边界是实际上传前，不因已配置 API key 就视为授权。图内提示注入只读不执行。
文件解析需像素／文件大小限额，限定资产路径并防 junction／symlink 越界；候选阈值待实施测量，
不能在未测前承诺抗所有恶意图片。无配置端点不扫网，不使用全局取消去中断他人 ComfyUI 作业。

## 6. 后端选择：能用就用，不绑死

| 能力 | 建议先复用 | 失败／缺失时的边界 |
| --- | --- | --- |
| 静态确定性加工／数值 | Pillow＋NumPy，适用复杂区域可选 OpenCV | 明确所缺能力，不为可选 CV 阻断所有本地操作 |
| 报告 PNG | 已有 Node／浏览器 helper 与 Rust outputs | 不可用明确失败，不静默转文字 |
| OCR／理解／图表 | 真正能接收图片的宿主；必要时千问／百炼现有入口 | 需记录真实模型；文本模型／命令存在不算识图可用 |
| 复杂抠图 | 已有可用 ComfyUI API workflow 或合适背景移除工具 | 无真实路径则 blocked；不能用简单 keying 假替代 |
| 替换性验证 | 窄调用形状与测试适配器；有条件再测第二真实后端 | mock 证明合同，不证明另一供应商已可用 |

不新造千问／百炼 SDK，不要求所有后端都安装。现有 CLI／文件调用足够时直接复用。
ComfyUI 只做请求、身份与结果对账，不接管服务部署／模型管理。rembg 仅候选，需重查 Python 与权重许可。

前轮只读观察（2026-11-14，**不是本轮活性探测**）：Python 3.14.10，Pillow／NumPy／pytest 可导入，
cv2／skimage 未装；另有 3.13／3.12。bl、ffmpeg、node、cargo 命令存在。只核过 key 已设置的布尔状态，
未验证鉴权、真实模型或 ComfyUI。installed/configured/probed/real-tested 必须分开，不预先标 enabled。

## 7. 身份、幂等、取消和恢复

- 重放身份绑定输入／资产 hash、操作、参数、profile、工具／模型／workflow 身份；复合图层顺序也参与。
- 同 run 同输入：先核已保存 manifest 与产物，成功则复用；同 run 异输入／参数冲突拒绝。
  明确新生成／刷新用新 run，不承诺模型输出逐字节一致。
- 先写独立 staging，验证返回路径、格式、尺寸、hash 和必要字段后完成结果；失败不覆盖旧好产物。
  并发与进程中断沿用已有锁／原子提交机制；缺机制时只补足已证明必要的本地边界，不另造总调度器。
- 远端提交后保留 job/run ID；超时或响应模糊先按该 ID 查询。没有可对账 ID 时报告 unknown，
  不声称 exactly-once，不默认再次付费提交。
- 取消只作用于本次所属任务；成功子项保留，其余明确终态。无法安全取消则停止本地等待并记录远端未知状态。
- 出错区分无效输入、不支持、未配置／不可用、权限不足、可重试故障、状态未知；按实际原因处理。
- 受损／缺失 manifest 不得 ready；保留诊断，不用 fallback 零值或模型“看起来没问题”掩盖完整性错误。

## 8. 蒸馏时必须修正的风险

前轮已对来源实现进行局部检查，以下是吸收方法时的风险，不表示本轮已修：

1. 旧 diff 先铺白底会掩盖 alpha-only 差异；需保留 raw 与不同背景可见差异两口径。
2. 旧 QC 的单连通域、半透明比例、边缘宽度硬阈值会误伤合法多主体／玻璃／阴影／像素画；
   必须有适用 profile 和控制题，不能把默认 keep-largest 当无损操作。
3. 旧 merge-over 遇尺寸不一致静默缩放；默认应拒绝，显式 fit 才变换。
4. white keying 会伤白色前景，不能可靠恢复复杂半透明主体；必须声明适用条件。
5. EXIF、P 模式透明、8/16-bit、预乘与颜色空间解释可能改变结果；先探测再显式转换／拒绝。
   R07 的逐通道 8-bit over 是声明口径的测试，不冒充所有素材的色彩管理标准。
6. 长图压成缩略图不能验小字；需真实分片、保上下文与坐标回映。
7. 同底层模型经不同入口不是独立评委；数值真值、人工观察与模型判定分别留证。

## 9. 验证、质量目标与交付建议

48 题和候选门槛以 [PRD §5](PRD.md#5-验收设计48-个逻辑项尚未执行) 为唯一提案清单；均未执行。
实现前冻结数据／配置／阈值和预算。安全／原件保护／假 ready 为阻断，性能先记录实际尺寸、机器、后端、
耗时与峰值条件，不虚构统一时延 SLA。复杂后端费用未知就不宣称成本已过关。

验证回传分层：

- 单元／契约：over、alpha、坐标、无损原件、异常、幂等与恢复负例。
- 功能单元／集成：制作→测量→诊断；模型真实读图；复杂真实抠图；正式 PNG 生命周期回归。
- 视觉观察：实际全局图、多背景与必要局部原分辨率，不以指标替代看图。
- 产品回传：题目、已知答案、真实答案／图片、身份、费用、失败与未测项；用户保留最终接受权。

两个 Skill 的静态质量、安装路径与逐文件 hash、路由正反例另验。宿主不可观测时只报显式调用／静态审阅，
不编造自动触发成功。48 项、旧回归、工具可替换与真实可用性不可合并成一个虚假满分。
