# 文件骨架与渐进补充

日期：2026-11-17。关联 #248／PR #249；上游为 DOC-REQ 的 REQ-09B。
本文件只说明当前已允许建立的文件骨架与角色，不把原提案的技术、参数或完整实施计划升级为采纳。

## 本轮确定的推进方式

用户要求先把骨架落盘，以文件继续推进，细节逐步补充。原始输入在 Git 外 recovery evidence。
不用先填完全部问卷，不等待市场／风险／种子信源全部确定才能整理文件。
也不把这个授权扩成真实抓取、付费订阅、金融代码、自动化或券商接入。

## 文件角色

私有工作区沿用 Assistant 根下的 `solutions/finance-stk02/`；实际路径由 DOC-USAGE／回执定位，
不新增环境变量，不把这里写成跨机器公共协议。沿用旧 `discovery-20261115/` 冻结研究 run，
不改其原文、manifest 或报告。

| 文件 | 唯一负责的内容 | 何时更新 |
| --- | --- | --- |
| README.md | 工作入口、文件导航、当前进度、下一步 | 每轮发生真实状态变化 |
| BRIEF.md | 当前个人设定、待定项、带来源的决定 | 用户补充／纠偏；Agent 建议单独标注 |
| SOURCES.md | 精选来源身份、准入范围、路线观察与证据指针 | 有具体来源／实际探针时；现在是空登记区 |
| RESEARCH-LEDGER.md | 证据索引、主张／预测冻结、结果裁决与来源能力 | 有实际证据／判断时；现在只有模板 |
| SIGNALS.md | 条件信号、弃权、影子跟踪与复盘 | 所需输入和适用规则明确后；现在只有模板 |

这些是一个研究试验的工作文件，不是第二套 Babata 产品权威、正式金融数据库或已发布 Skill。
当前不固定 JSON schema、创建 SQLite、运行抓取任务或新增代码层。记录量和实际 caller
出现后再决定如何结构化，不为“骨架”提前建设空服务／CLI。

## 后续每次补充怎么落

1. 先保留有治理意义的直接原话与时间，再归入对应工作文件。私有原话、来源、预算、
   风险和个人决定留 Git 外；公开仓库只接纳审阅过的通用产品变化，不自动同步私人内容。
2. BRIEF 中未确认值保持待定；来源名、期限、风险、阈值不因 Agent 举例而生效。
3. 仅更新受影响角色与进度，不每次重新生成整套方案；变更已有决定时保留出处与取代关系。
4. 原文／必要版本／结果证据在 Evidence，工作区引用；冻结的预测和裁决只追加修正，
   不覆盖旧口径、不将后来知道的信息倒灌历史。正式入库仍走原有 Rust writer。
5. 返回本轮改了哪里、哪些还未知及下一件可做的事；收到一条细节就能推进一小步。

## 本轮骨架验收

- 工作入口能找到四个工作文件和上轮冻结研究；新文件可回读、链接有效。
- 已知目标与未定参数分开；没有自填信源、ETF 代码、评分、收益、概率或仓位。
- 记录模板明确区分来源／观察、预测／结果／裁决、信号／执行，证据与重放边界保留。
- 私有内容不进入公开提交；不设置环境变量、不安装、不合并、不启动自动化或交易。
- 文档检查只证明骨架与权威一致，不证明预测／收益／数据接入能力。

当前完成状态与验证结果只见 DOC-USAGE 和 Git 外回执；此文件不维护第二份实时计划。
