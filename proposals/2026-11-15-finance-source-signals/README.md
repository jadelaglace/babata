## 1. 一句话结论

建议把它做成 Babata 的一个**受私人规则约束的金融研究与信号应用**：
精选来源，保全当时信息，持续检验谁在哪类问题上有增量价值，再把通过检验的证据转成
面向 ETF／板块／宽基的中短线信号；没有优势就观察或不行动。

不是全网资讯聚合器，不是把大模型情绪值变成买卖点，也不是先做 QMT 自动交易系统。
“私人规矩信托”暂按用户规则约束、可审计、由用户决定的架构类比理解，
不是法律意义上的信托、资金托管或收益保证；具体含义仍向用户开放。

## 3. 成熟方案：复用零件，不照搬整车

以下为官方文档／项目或原始论文的实际正文／相关摘录核实，访问日 2026-11-15。
它们证明有相关机制，不证明本机可用、A 股适配、数据正确、投资有效或用户已同意依赖。

| 候选 | 已核实的用处 | 缺口／取舍 | 建议位置 |
| --- | --- | --- | --- |
| [FreshRSS API](https://freshrss.github.io/FreshRSS/en/developers/06_GoogleReader_API.html) | 订阅管理与 Google Reader 兼容 API；API 需单独启用与鉴权 | 不解决预测校准、历史首发真伪或付费全文；新增服务有运维成本 | 需要多订阅运营时可选；首轮优先来源原生 RSS／已有工具 |
| [FinRobot](https://github.com/AI4Finance-Foundation/FinRobot) | 将代码中的确定性金融计算与 LLM 推理／解释分开，强调结果溯源 | 官方自述不等于实证；以股票研究／估值等为主，不能直接替代本需求 | 借计算／叙述分离；不引入整套多 Agent 框架 |
| [Qlib](https://github.com/microsoft/qlib) | 研究工作流、模型和回测相关基础；有 PIT 路线 | 更偏量化研究平台；示例数据质量有官方警告，不能拿来即作可信历史 | 复杂研究需求出现后再评估，不先建因子工厂 |
| [Qlib PIT](https://qlib.readthedocs.io/en/latest/advanced/PIT.html) | 保留发布与修订版本，避免用后来的数据回测过去 | 财报 PIT 不自动覆盖作者删改帖、系统首次见到时间与 ETF 当时池子 | 采纳其防泄漏原则；账本按真实信源扩展 |
| [vectorbt](https://vectorbt.dev/getting-started/features) | 快速信号评估，支持成本／滑点；官方例子区分信号形成与下一时点成交 | 通用引擎不是 A 股市场规则库，不自动解决涨跌停、交易单位、退市和修订数据 | 首轮回测引擎候选；窄调用并锁版本，选型前核许可证／免费与 PRO 边界 |
| [Metaculus 历史评估方法](https://www.metaculus.com/notebooks/16708/exploring-metaculuss-ai-track-record) | 讨论 Brier、校准与问题难度，提示分数不能脱离题集直接比较 | 不是金融收益验证；此文不代表其当前平台积分合同 | 借概率评估方法，不把任意评论强行转成概率 |
| [Tushare ETF 日线](https://tushare.pro/document/2?doc_id=127) | 明确提供 ETF 收盘后历史日线及接口权限说明 | 有权限／成本条件；单一行情接口不提供完整宏观 vintage、源内容历史或成交仿真 | 与用户已有行情源比较后选一种，不默认采购 |
| [统计局发布日程](https://www.stats.gov.cn/xxgk/sjfb/fbrcb) | 提供宏观数据发布日程入口，可作事件时间基准来源 | 日程不是当时数据快照；发布值、修订值、预期值必须另取并留版本 | 一手事实层候选，结合央行／交易所／基金公司等逐源核验 |
| [迅投 XtQuant 交易文档](https://dict.thinktrader.net/nativeApi/xttrader.html) | 报单、撤单、资金／持仓／订单查询及回调；需与 MiniQMT 交互 | 未核用户券商、开通条件及版本权限；文档还提示断线需主动重连 | 仅未来执行端候选，不是当前数据／信号链前置 |
| [回测过拟合原始论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) | 区分样本内选择和样本外表现，强调尝试多种策略后的选择偏差 | 没有一种方法能保证未来收益；样本稀少更不能装统计确定性 | 保留实验账本、滚动样本外和前瞻验证；复杂 PBO 估计按需要再加 |

结论不是“没有现成产品”，而是已核候选各自覆盖局部；本轮没有核实一个现成方案能同时满足
私人精选来源、严格时间回放、来源能力校准、A 股 ETF 低频信号与用户审批全部要求。
因此先用成熟工具搭窄闭环，比整套接入某个金融 Agent 或重写量化框架更贴合现阶段。

## 4. 最小业务架构

```text
用户的投资政策／目标／不可做的事
                 ↓
精选信源 → 可回放证据 → 冻结事实主张／预测／假设
                            ↓             ↓
                    事实与事件核验   到期结果＋同题基准
                            └──────┬──────┘
                         分领域／期限的信源能力档案
                                   ↓
              宏观／行业假设 → 资产映射 → 价格与风险过滤
                                   ↓
                   观察／冲突／弃权／可解释信号卡
                                   ↓
                      用户判断＋影子组合与复盘
                                   ⋯
                   未来：明确审批 → 执行适配 → 对账
```

这是职责划分，不是十个新服务。建议仍为本地模块化单体／现有宿主驱动，
Codex／Claude 可做研究与编排；确定性身份、版本、计算与状态逐步沉入 Rust。
Python 回测库可作替换工具，不要求 Rust 重写成熟算法。

### 4.1 三层约束

1. **个人政策层**：市场与资产范围、期限、风险预算、仓位限制、禁止动作、通知偏好。
   参数由用户决定；没有它们，只能给观察／研究信号，不能算个性化仓位与下单建议。
2. **研究与信号层**：来源观察、证据抽取、预测冻结、评分、资产映射与候选行动。
   不能改个人风险政策，不能把网页里的指令当操作授权。
3. **执行层**：未来才加入。单独校验审批、账户、金额、时效、价格边界、幂等和成交对账。
   “来源可信”及“信号强”都不能跳过用户审批。

本轮只设计前两层，不实现第三层；“先不自动交易”也不等于偷偷建可用下单入口。

## 5. 精选信源：不是多抓，而是知道为什么看

每个来源登记身份／平台／作者、领域与覆盖、已知利益冲突、可用路线、授权／费用、
历史可得性、更新时间与失联状态。分类是角色，不是无条件可信排名：

- 一手锚点：统计、政策、交易所／基金公告等，解决“实际发布了什么”；解释和数据也可能修订。
- 解释来源：少量用户认可作者／研究机构，解决“如何理解及可能影响”；仍需检验。
- 市场验证：可用行情、基金资料、交易日历，解决“是否已反映、能否映射和交易”。
- 探索候选：有预算的小池，保留加入原因，不因一次爆红立即变核心来源。

Babata research 负责有目的的发现、补证和查原文；固定来源的稳定更新优先用原生 API、
RSS、授权导出或现成 CLI，不反复用搜索结果假装完整订阅。暂不能自动取的可人工交材料，
明确 coverage 与失败，不绕登录／付费限制；微信 UI 仍受现行单独授权边界约束。

首次取回、无变化、修订、删除、不可访问是不同观察。相同内容重复抓取不增加预测数；
转述保留祖先来源与传播簇，十个转载不能算十份独立支持。

## 6. 可检验主张与时间账本

候选最小对象：Source、Observation、Claim／Forecast、Outcome、Assessment、
SourceProfile、Signal；名字不构成新公共 schema 承诺。先用文件实测再定存储合同。

### 6.1 一条可评分记录需要什么

- 来源原文／必要上下文与定位、内容 hash、版本、作者归属、采集完整性；音视频保留必要片段定位。
- 断言的对象、方向／事件、预测期限、作出时间、明确条件、失效条件、判定规则及结果真值来源。
- 原文概率与 Agent 解读分开；原文没有 70% 就不能伪称作者给了 70%。
- LLM 抽取属于候选；关键歧义人工确认，仍不明确则不可评分，而不是事后挑最有利解释。
- 事实陈述、解释、预测、条件判断与交易建议分型；“可能有机会”可留作背景，不强凑命中率。

例如“政策转暖利好科技”不足以自动算一次预测正确；需事先确认它是在说政策事实、
行业经营、指数相对收益还是某期限 ETF 涨跌。行业上涨也不自动代表任一同名 ETF 可获同样收益。

### 6.2 至少分清这些时间

`event_time` 事件发生、`published_at` 来源声称发布、`first_seen_at` 系统首次实见、
`ingested_at` 入账、`revision_at` 修订、`eligible_at` 策略可使用、`tradeable_at` 最早可成交。
保留时区、未知值与可信依据；历史页面写着旧日期，不等于系统当年已拿到且正文未改。

三个研究等级分开报告：

1. **历史回顾**：今天补采旧内容，只能研究候选假设；若无法证明当时版本，不称严格历史可交易。
2. **可证明 PIT 回放**：按当时版本／发布时间／可得性、当时资产池、源名单和权重重建。
3. **前瞻影子验证**：先冻结主张、政策和信号，再等结果到来；最能避免解释倒灌，但需要真实时间。

2026 年挑出的“高手名单”不能直接回放到更早年份，宣传成当年可做到的收益。
到期评分仍可用后来数据裁决结果，但不能倒灌给历史决策。

## 7. 回溯置信：学会该听谁的哪一部分

不做一个全局“此人可信 92 分”，建议维护可解释档案：

| 维度 | 要回答的问题 | 不能替代什么 |
| --- | --- | --- |
| 事实可靠性 | 陈述与后续一手证据是否一致、会否更正、证据覆盖如何 | 不等于预测成功率 |
| 预测能力 | 在同主题、同期限、相近问题难度下，是否胜过基准 | 不等于诚实／内幕／人品 |
| 提前量与信息新颖度 | 相对首次公开信息／其他来源是否更早且确有内容 | 不把无法验证的首发时间当抢先 |
| 投资增量 | 映射到可交易资产、扣成本并经过风控后是否改进结果 | 不把方向准当赚钱，也不把赚钱当事实为真 |
| 独立性与稳定性 | 是否互抄、收益来自少数运气、特定阶段或后来挑选 | 不用转载量和粉丝量当独立证据 |

可评分的二元概率预测可用 Brier：`(p - outcome)^2`，越低越好；与同题／同截止点的
基准对照，同时看校准和区分度。0.25 只对应始终报 50% 的特定二元基准，不是所有题的及格线。
方向、数值、条件事件用各自事先冻结的规则，不混合成假精确总分。

来源权重是版本化的研究决策，不是声誉裁决：

- 按主题 × 期限分组，必要时标市场状态；不要切太细造成每格只有一条记录。
- 报全部符合范围的预测、可裁决率、样本数／有效独立样本与不确定区间，不只报成功案例。
- 小样本向中性／先验收缩，逐步更新且保留变更原因；不因一次命中暴涨权重。
- 没有内容或无法裁决标 unknown／unresolved，不随意计错或从分母隐去。
- 减少重叠事件／持有窗口造成的伪样本量，监控风格漂移和失效，不永久封神。
- 分开记录作者主张质量、Agent 抽取错误、系统预测质量和模拟组合收益，错不甩给作者。

用户直觉中“说得准的人值得多听”保留，但系统只能证实可观测的准确性、提前量和增量，
不能据此断言“离内幕近而且说真话”。不以获取非公开重大信息作为产品目标。

## 8. 从蛛丝马迹到信号，不跨过证据边界

宏观／行业分析保留传导链：观察到的发布／政策 → 可能的经济或行业影响 →
受益与受损对象 → 映射工具 → 时间窗口；每条边标支持、反证、条件和未知。
“为什么不是相反方向”“是否早已计价”必须有位置，图不是因果证明。

信源能力仅是一个输入。最终还需价格／波动与流动性、信号冲突、个人风险规则、
信息陈旧度和 ETF 映射有效性过滤。不能因为一个人过去准就无条件跟单。

候选信号卡至少含：

```text
状态：观察／证据冲突／弃权／条件信号／失效／已到期
信息截止点；有效期；策略／来源权重版本
主题与可选 ETF／宽基映射（不是已下单）
方向、期限、触发条件；价格已反映的检查
依据：原文、支持／反证、来源能力与样本限制
失效／撤回条件；数据缺口与不可量化风险
候选行动及不行动选项；政策允许时才给仓位上限
影子跟踪结果与到期复盘入口
```

此处置信度是本信号／证据的评估，不是把作者准确率直接写成获利概率。
第一轮可只输出研究观察卡；没有政策、历史或风险数据时不能伪装成明确可执行荐买卡。
推送复用既有 IM／邮件能力的授权入口，先产本地报告；不在本轮发消息或创建自动化。

## 9. StockMesh：有可借部分，但不是现成股票引擎

本机只读核对 `StockMesh` HEAD `66fe575` 的 README、状态及架构／Skill 契约局部。
其当前主要用例是组织／社会网络情境分析，名字不能当作已有金融能力的证据。
仓库存在用户未提交文档，未修改或执行它；部分候选文档不等于已实现。

值得借鉴的有：cutoff-bound 事实网络快照、事实／主张／假设分型、
冻结预测对后续现实的 assessment、未知／冲突／coverage，以及模型或方法校准与对象主张分离。
其真实 provider 质量、真实工作流用途及人类验收仍明确开放，不能声称能直接发现投资机会。

建议先借原则，不依赖代码。未来有明确金融案例时，让可选适配器读取最小授权证据包，
返回带 cutoff、证据引用与不确定性的分析候选；不共享主库，不导入私有案例，失败不阻断账本。
只有证明比人工／直接 LLM 分析更有价值再接，图谱与分析性能需分别验收。

## 10. 哪些原子化，哪些不要拆

| 能力 | 当前动作建议 | 边界 |
| --- | --- | --- |
| 搜索／核证／研究回执 | 复用 babata-research 与宿主工具 | 不把金融源评分塞进通用搜索技能 |
| 来源更新观察、快照／diff、去重 | 从首个真实来源补窄缺口；第二个 caller 证明复用再提炼 | 不先造覆盖所有平台的订阅总线 |
| 主张／预测冻结和后验评分 | 先在本业务模块实现可测函数／CLI；规则、输入、结果版本化 | 不自动升级为跨领域知识本体或通用评分服务 |
| 行情与回测 | 现成数据源＋窄 Python 工具适配，确定计算不交给 LLM | 金融日历、单位、资产映射、成本归金融域拥有 |
| 信号政策／风险约束 | 金融应用层的可测试规则 | 不放进通用 collect／clean 或 StockMesh |
| 报告、PNG、通知 | 复用现有 render／IM 路线；无明确展示需求先 Markdown | 输出不决定证据真值，通知不等于执行 |
| StockMesh／未来券商 | 可选适配 | 主链不依赖，不能直接写正式数据或越权执行 |

建议先一个面向用户的金融研究业务入口，内部组合几个确定性命令；
不是每个对象、打分公式都建一个 Skill。Skill 只负责触发、范围、调用和回读，
Rust domain／application 持有确定性规则与正式 writer，适配器返回候选。
宿主与执行方式不锁定 Goal／vibe／某个 AI。

已合主干能力与独立发布、安装状态需分开：本提案基于主干 `67fba31`；
研究包可搬走等后继工作仍在 #238／#247，未据文档或本轮调用声称它们已合并／发布。
本轮用既有 helper 留研究证据，不新建金融 Skill。

## 11. 数据、权限与幂等

- 沿用四根，不建第五根。Assistant 放研究工作区／实验／可重建信号草稿，Evidence 放必要
  原文／时间版本／裁决／人工决定／运行身份等持久证据；Recovery 按既有策略，
  Data 只在明确正式接纳且通过既有 Rust writer 后进入。前瞻金融账本是否需独立于知识
  canonical 的持久存储，待首轮方案采纳时再定；不得借 proposal 绕过唯一 writer。
- 不是每条新闻都要 C0→C1→C2；观察和助理研究可直接形成草稿／信号。
  但要回溯评分的最小必要证据不能清洗完就删。公开内容也要尊重保存／再分发权限，
  不能只留 hash 就声称原文可审计；保存受限时明确限制。
- 原件版本、观察、抽取结果、裁决、权重版本与输出分开；改变模型或规则产生新分析，
  不回写原预测。来源对象 ID＋revision/hash 区分重采和真修订；同内容不同传播上下文仍保留。
- 评分键包含预测、结果证据、rubric 和计算版本；重复执行不重复计分、不污染权重。
  信号键包含 cutoff、输入集、政策与权重版本；通知另记投递状态，不承诺跨系统 exactly-once。
- 明确 failed／inaccessible／stale／unresolved；一源失败不删成功项，必要证据缺失则该项弃权。
- 数据源 token／券商凭据不进仓库、文档、提示词或回执；用工具既有安全配置和引用。
  不设置用户环境变量或 PATH；依赖／缓存遵循工具默认位置，不塞进四根。
- 网页／附件／作者内容是非可信数据，不能下达系统命令、改权重策略或授予账户权限；
  模型只提候选，代码验证 schema／引用／时间／权限，关键裁决留人。

## 12. 分期计划与退出门槛

这些是建议交付切片，不是已经创建的多个实施 Issue，也不是承诺几个星期就能验证投资有效。

| 阶段 | 具体交付 | 何时算到终端 |
| --- | --- | --- |
| 0 约定首轮 | 市场／期限／不碰范围、种子来源、历史可得性与费用、试验基准 | 用户确认范围与风险语义；没有资金／密码也能启动研究 |
| 1 精选来源账本 | 少量授权来源真实取回，观察／版本／失败分开；支持人工补材 | 原文可回读、重采不增版本、删改留痕、明确覆盖；跑通一个真实来源到研究卡 |
| 2 可检验预测与回溯 | 人工审阅抽取、冻结rubric、到期裁决、按主题期限的来源档案 | 分清历史回顾／严格PIT／前瞻；能解释每条评分、未知和样本限制 |
| 3 影子信号 | 有限ETF池、市场过滤、可解释卡、纸面跟踪、基准／消融与成本 | 同一输入可复现；样本外及前瞻结果如实报告；证据不足允许不出信号 |
| 4 使用反馈与加固 | 根据真实有用性增减来源、调通知、再决定值得泛化的原子 | 用户认为降低决策负担；漂移、失败与风险策略可检查，不以多做功能代替效果 |
| 未来独立决定 | 明确批准后的执行适配或仅通知 | 另行授权、券商和规则核查、纸面／沙盒、审批失效与对账验收；本轮不启动 |

首轮规模仅作为可讨论起点：可先 3–5 个解释来源＋一手锚点、5–10 个候选 ETF，
收盘后／每周整理而非盯盘。具体数量、期限、刷新频率、成本和统计通过线由范围与数据决定，
不是默认开通订阅或用户已采纳的参数。初期优先一个主题到一张可检验卡，不铺完整市场。

### 12.1 回测必须回答的五件事

1. **当时能否知道**：可得性、修订、源名单／权重、ETF 上市／退市与历史映射；
   当天收盘信号不拿当天已结束的收盘价假装事后成交。
2. **是不是挑出来的**：保留试过的规则／参数／作者名单及失败试验，时间顺序滚动训练／测试；
   有重叠目标时隔离边界，锁定最后评估集，不能边看结果边调到好看。
3. **和什么相比**：事先选择适用的持有基准／现金基准／简单价格规则、等权来源与动态权重；
   做去掉来源权重／消息分析的消融，看增量是否真实存在。
4. **真能这么交易吗**：手续费、买卖价差、滑点、分红／复权、交易日历、单位、停牌、
   涨跌限制、流动性与 ETF 特定交易规则；不可成交不能强制填单，不能假定所有 ETF 同一规则。
5. **结果有多可靠**：报告净收益／相对基准、最大回撤、换手／暴露、交易数和成本敏感性，
   以及分阶段表现／不确定性；少量低频事件不足时明确“不足以下统计结论”。

系统可能诚实地得出“这些来源没有可交易增量”，这也是有效研究结论；
通过工程验收不等于策略可实盘，历史好看不等于达到用户风险要求。

### 12.2 实施前拟验收用例

| 场景 | 预期结果 |
| --- | --- |
| 同条内容重复取回；十个转载 | observation 可追加；内容版本／独立预测数不虚增，传播关系可查 |
| 作者事后改预测／旧网页新采 | 保留前后版本；旧决策不能用后修文，未知当时版本降级回顾 |
| 模糊／条件未发生／未到期 | 明确不可评分／条件未触发／pending，不能强判对错或删分母 |
| 作者没给概率，Agent 自己估了概率 | 两者分开评分，不归因给作者 |
| 一次命中、新来源、样本不足 | 权重受样本与不确定性限制，保留中性／观察状态 |
| 未来数据、后验源名单进入旧 cutoff | 回放拒绝／显式降级，不能输出严格PIT成绩 |
| 行情单位错误／ETF 当时未上市／不可成交 | 失败或跳过并给原因，不造价格／成交 |
| 情绪很强但证据冲突／风险越界 | 弃权／观察；不能被 LLM 绕过确定规则 |
| 模型幻造引用／网页要求执行命令 | 引用校验失败；网页无权限触发命令或金融动作 |
| 同一裁决或通知任务重试、中断恢复 | 不重复计分，不改原预测；投递状态独立核对 |
| StockMesh／单来源不可用 | 显式降级；不影响无依赖已成功项，不伪称分析通过 |
| 用户要信号但无个性风险参数 | 研究观察卡，不凭空给仓位／下单；本轮不存在可调用下单入口 |

以上仅为拟定用例，未运行，未宣称通过；实现后需冻结输入与版本，合成机制测试与真实用途
验证分别留证。来源权重能否改善结果需样本外／前瞻验证，不能用这些机制用例证明。

## 13. 需要用户配合，及目前不需要什么

下一步真正开工前，优先确认前三项；预算／渠道可在采集探针时再收窄：

1. **市场与期限**：是否先 A 股场内 ETF？中短线更接近几天、几周还是 1–3 个月？
   港美／QDII、个股、杠杆是否先排除。
2. **种子信源**：提供少量你真正在看的作者／渠道或几篇代表作，尤其是你想检验的人；
   历史档案、登录／订阅权限在工具安全配置中提供，不把密码贴聊天或仓库。
3. **私人规矩**：允许的风险和禁止动作；现阶段可先给大致可接受回撤／频率，
   未确认前不生成个性化仓位和交易指令。
4. **数据与预算**：已有行情／宏观数据账号及历史材料是否可用；可接受的数据订阅和模型调用预算。
5. **使用方式**：先本地报告还是以后飞书通知？偏固定复盘还是仅重要变化？本轮不实际接推送。

现在不需要真实资金规模、券商密码、开户、QMT 运行环境，也不需要先完善 StockMesh。
不要求用户帮忙选框架、设计表结构或陪跑每个工具。技术探针与证据整理由 Agent 承担。

## 14. 决策点与本轮交付边界

建议下一次只批准“阶段 0–1 的一个主题／来源真实闭环”，完成后再评估扩展；
不要一次批准全自动交易或通用金融平台。此建议待用户选择，不自动开工。

本轮提供的是需求与候选路线；未运行金融回测、未验证任何作者或信号、未安装上述候选、
未调用付费行情、未改 WBS／StockMesh、未接券商或自动化，没有收益承诺。

受影响权威：REQ 仅记录用户已明确的新探索目标；本候选文档负责外部方案与计划；
Usage 记录本轮交付事实。现行 PRD／AC／Architecture／TC 及 Routes 复核后不改：
