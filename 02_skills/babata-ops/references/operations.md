# 开发环境与服务变更

## 环境与配置

先核 OS／架构、现有 manager／版本、磁盘和权限。优先 PATH、工具自有配置、lockfile、
官方默认缓存。多版本先核解析路径，不为单项目升级全机或移除旧环境。Python 按项目用
uv／PEP 723、Node 用 lock 和包管理器，不引入每工具一个私有变量，不把第三方缓存／
权重／runtime 塞进业务根或 Git。持久 PATH、用户变量、系统服务和安全设置变更需请求
包含相应范围；原生配置够用就不造新配置层。
秘密用原生安全配置／OS secret store／受控 manager，最小权限；.env 只是文本不是加密，
不提交／整份输出，不在此重做已有秘密基础设施。

## 部署与重启

1. 核角色、精确 service／host／环境、期望 commit／artifact digest、范围及停机容忍度；
   查现状、空间、配置和有状态依赖。未知机器按开发／有状态保护。
2. 核已知好 artifact/config、schema 可逆性和数据备份；迁移未证明可逆时，代码 rollback
   不是完整恢复。记录停止／回退条件与相应授权。
3. 复用既有发布路径，准备确定版本 artifact／独立 release 目录，用既有 manager。不能
   默认 reset --hard/clean；部署机也先查 dirty/untracked、配置／数据分离。人类编辑工作树
   不变，仓库操作按 Git 流程。无真实必要不引入新平台。
4. 按合同 drain／有界等待再切换；单机不能真正 canary 时如实声明停机与回退条件。只改
   精确目标，失败不扩大到全机重装。
5. 核 manager、实际版本、readiness、关键真实请求和必要观察窗口；200／端口监听／exit 0
   不能独证用户路径成功；失败按已授权恢复计划处置。

systemd Type／Restart／TimeoutStopSec、容器、Windows Service 依实际服务选择，不把
nohup 当完整管理。避免未受控后台进程、无界重启和未声明全局 sudo。

## 幂等与未知结果

目标满足报 unchanged，别用重启代替检查。重复配置确有需要才用 Ansible 等现成工具，
不强装；check/diff 是模拟，不证明执行，部分任务不支持或可能强制执行，diff 会泄密。
超时／断线先核运行版本、job/migration ledger、健康配置，不盲重投。

## 备份与恢复

声明范围、唯一内容、保留／加密／访问和一致性条件；活数据库用应用支持的 snapshot/
backup，不把随意拷文件当一致备份。核 hash／可读性，在隔离目标 restore 后核数据、
schema、依赖、权限与关键请求。不覆盖活动数据、不删唯一旧好备份腾空间；真实删除按
精确授权，只有演练成功的范围可称可恢复。

## 回执

写目标授权／角色、前后 artifact/config/service 身份、动作和未做项、探针／日志时间窗、
真实请求、失败及恢复事实和剩余风险。秘密／私有 inventory 留受控本地，公开仅安全摘要。
架构、代码和运行缺陷分别交回拥有者，不自行扩大实现。
