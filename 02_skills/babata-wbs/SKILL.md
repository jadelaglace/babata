# Babata WBS

把 WBS 意图交给独立业务 Skill 和现成 CLI。飞书多维表格拥有任务数据；
不创建本地任务主库、同步、Goal、调度器，不启动知识宇宙收集/清洗。

## 固定调用独立业务源

从目标宿主的 `.agents/skills` 安装根定位并完整读取 `feishu-wbs/SKILL.md`，
按其引用加载当前 `lark-base`，认证问题再按 `lark-shared` 路由。
目标/排序等分支资料按业务源指引按需读取。

不调用 Hermes 或旧名 `feishu-wbs-task-management`，不自动合并它们的修改。
找不到独立版本就报告缺依赖，不猜表坐标、不换飞书原生 task、不复制另一套配置补洞。
表坐标、字段、ID、循环任务、复盘和排序规则只维护在该业务源；
当前 CLI/help/schema 决定命令语法，凭据由 CLI 管理。私有任务、payload 和回执留在 Git 外数据根。

## 识别本次请求

| 用户说法 | 交给业务源的操作 |
| --- | --- |
| 今天做什么、查待办、WBS 复盘 | 查询；手动复盘默认只摘要，明确要分析才给意见，不自动改表 |
| 更新下我的 WBS、根据目前进度刷新 WBS | 对账本次明确关联的进度，只写有证据的差异 |
| 新建个待办，xxx、加个任务 | 按业务规则先查重，再新建或返回已有任务 |
| 只看预览、dryrun | 只预览；任何 CLI 写命令带 --dry-run，不自动转实写 |

触发话语不是在没有具体内容时凭空造任务的授权。明确新建/更新不反复逐项审批；
歧义、纯建议和结构级重排按业务源的边界处理。代码计划、Issue 拆分不因提到“任务”就写 WBS。

## 结果

按业务源完成 schema 核对、当前记录对账、最小写入和必要回读；不在薄路由另维护一套规则。
每项报告“任务ID + 人话标题”、变化/未变化/待确认/失败/未知，说明下一动作。
区分宿主发现、合成请求 dry-run、模型自动选择和真实读写回读；只声明实际验证到的层次，
不输出凭据或无关个人数据。
