# Babata WBS

拥有与存储平台无关的个人 WBS 语义、汇总模板和维护规则。任务当前值由用户选定的任务源拥有；
当前在线任务源为飞书，由本机独立 `feishu-wbs` 适配。这里不保存任务快照、私有表坐标或凭据，
不建本地任务主库、同步器、运行时 Goal 或调度器，也不启动知识收集或清洗。

## 选择工作

| 用户意图 | 操作与按需资料 |
| --- | --- |
| 汇总 WBS、最新状态、复盘、今天做什么 | 只读；读取 [汇总规则与模板](references/summary-template.md)，按请求范围汇报 |
| 更新进度、记录感悟、纠正某条内容 | 对账明确目标，只提交本次有依据的差异；保留无关正文 |
| 新建待办、加一本书 | 先查重和历史 ID，再创建；书加入已明确的伴读父任务，不自动改排程 |
| 一组目标、改名、TOP 排序、父子或前置 | 先读 [目标与排序](references/goals-and-ordering.md) |
| dry、预览、dry-run | 只读与预览，不实际变更；后端预览也必须使用其 dry-run 能力 |

缺少具体进度不能凭触发话语造完成度；代码 Issue 和 Agent 计划不因出现“任务”而写个人 WBS。
手动复盘默认摘要，不打健康分、不夹带未请求的建议或预测；明确请求分析时将事实和意见分开。

## 使用任务源

- 用户已提供足够数据时，可离线应用本 Skill 汇总，注明来源、观察时间和完整性；
  没有最新读取不能称实时。缺少状态、归档等必要字段时标明统计缺口，不将未知当作确定值。
- 需要读取当前飞书值或实写时，完整读取宿主 `.agents/skills/feishu-wbs/SKILL.md`，
  由它处理 Base 坐标、schema、字段映射、CLI、身份、分页和读回；公共正文不写这些实现细节。
- 适配层显式调用本 Skill 时只补读未加载的规则，不相互递归启动。缺适配器就说明缺依赖；
  不回退 Hermes、旧 WBS 副本或另一任务产品，不复制第三份规则补洞。
- 私有临时导出与 payload 放 `BABATA_ASSISTANT_HOME/solutions/wbs/workspaces/<run>/`；
  持久快照、schema 观察与写回回执放 `BABATA_EVIDENCE_HOME/wbs/`；辅助脚本放方案 `runtime/`。
  不进入代码仓库或知识数据根，不自动晋升 C0，旧回执原字节保留。

## 个人任务约定

- 优先级为 S/A/B/C/D；S 表示紧急重要，D 为创意池。状态分别为待开始、进行中、等待、暂停、完成；
  暂停保留原因及用户明确的恢复前提，不自动恢复。状态、优先级、TOP 和百分比是独立信息。
- 新普通任务默认 A、L4任务、待开始、未归档；新创意任务默认 D、L4任务，并说明预期产物。
  无计划日期或进度就留空；这些默认值不覆盖已有任务。愿景、大目标、长期目标、任务是层次语义。
- 任务 ID 通常为大类-子类序号，现有大类包括 TEC/HUMAN/CAREER/FINANCE/SIDE/LIFE/IDEA/BABATA；
  新 ID 沿对应前缀最大序号递增，核对范围包含归档记录；保留历史非规范 ID。
  创意用 IDEA-主题序号；一堂开放麦沿用 HUMAN-YITANG 系列，不混成 MBA。
- 每条用“任务ID＋人话标题”识别；业务 ID 可能重复，同名或近义不等于同一任务。
  本地目录只记录已确认的对应关系，文件存在、目录名、建 Issue 或计划日期都不能推导实际进度。

## 更新与内容边界

1. 将用户明确意图与当前记录对账；重复 ID、语义歧义只停住受影响项。相同值不提交。
   百分比只来自明确用户判断或可回溯证据；未知不补 0，不把历史摘要百分比悄悄填进数值字段。
2. 明确新建或更新不逐条重复审批。涉及结构重排按目标与排序约定处理；纯建议不自动写入。
   状态用用户原意，不把暂停代成等待，也不凭已有百分比自动改状态。缺目标状态由适配层报告或
   在用户已明确授权该选项时最小扩展；不静默修改其他记录或改变整列类型。
3. 感悟以用户自述记录，保留有意义的来源与日期；个人体会不写成已核实的客观定律。
   用户为解释或纠偏举的例子不是待保存正文。要求“改清楚原来这一处”时只修该处，不把争论、
   道歉或整段消歧解释追加进任务，不自行扩展作者、案例和讲解方式的含义。
4. 保留与本次无关的摘要、关系、日期与进度；摘要较长可补详情，但不能清空摘要仅留详情。
   写前重读涉及字段；冲突只停该项。写响应、最终回读与用户验收分开报告，不承诺无竞态。
5. 新建先检查归档与未归档；匹配已归档任务先报告，不自动复活或新建近义副本。
   普通明确任务可直接完成创建；后续任务、前置任务或能量管理任务不因备注提到就自动另建。

## 循环与结果

- 改为循环任务不增加完成次数；保持进行中。一次实际闭环才加 1，并在摘要记第 N 次内容和可识别事件。
  同次重投不重复计数；无法区分同次和新轮时只澄清此项。循环闭环不关闭整条任务、不归档，
  用户明确结束循环再处理。
- 汇总按模板列范围与完整性；变更报告“任务ID＋标题”、已变／未变／冲突／失败／未知，
  说明实际验证层次。未知结果先核对，不能盲目重建、重加计数或重写整组。
- 当前任务状态只存任务源；模板与规则不固化本次任务、数量、进度或个人感悟。
