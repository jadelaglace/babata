# Browser and Desktop UI Recipe

Browser, Chrome, Lark, and Windows desktop-control Skills are tools used inside a source recipe.
They are not a source identity and cannot turn an unknown/disabled platform into an enabled route.

## Routing

Map the user's platform first: Feishu, Yuque, WeChat, Zhihu, Bilibili, Xiaohongshu, Douyin, Doubao,
Kimi, ChatGPT, browser bookmarks/pages, local files, or another explicit source. Then check the exact
`source.*` runtime capability. If absent, disabled, or unavailable, report the route gap and stop
before formal collection.

Do not fall back from a named platform to `source.browser_pages`. A saved title/URL or visible page
does not prove that platform's candidate discovery, content, attachments, or recollection semantics.

## Acquisition Tool Rules

- Prefer official export/API/CLI and mature installed tools before browser automation.
- For current Codex recovery, reuse the user's existing signed-in Chrome or official desktop app
  only within the named scope.
- Do not ask the user to transcribe passwords, cookies, tokens, export paths, or metadata when the
  Agent can inspect or invoke the official UI safely.
- Never bypass access controls, decrypt private application databases, install interception
  certificates, or scan process memory.
- Keep downloads transient until an enabled Babata route formally saves them.

## Unknown Sites and New Content Shapes

For an unknown site, do read-only investigation of official export, API/SDK, maintained CLI/plugin,
and generic Agent browser feasibility. Record attainable body, hierarchy, attachments, history,
recollection, minimum authorisation, and limitations in a normal Babata Issue. Do not claim
collection before real evidence and capability activation.

For a known source's new image/audio/document/reference shape, extend its existing recipe and tests.
Do not create a new user Skill or route solely for the format.

## Special Boundaries

- WeChat uses the official PC UI only; unavailable visible data stays restricted/failed.
- Douyin and WeChat Channels remain deferred until the user explicitly re-enables them.
- Browser bookmarks are last priority and must eventually auto-traverse page bodies and obtainable
  attachments; manual per-bookmark clipping is not acceptance.
- First-party creation uses Workspace create/revise/annotate semantics, not a collection adapter.
